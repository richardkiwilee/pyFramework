# 战斗引擎采用「同步预计算 + 播放队列」

战斗引擎在每回合开始时**同步算完全部行动的结算**（伤害即时生效），UI 层通过 `next_action()` 轮询播放队列逐条展示。这是 demo-1 已验证的「先算后播」模式，而不是 AbilityKit 那种逐帧实时管线（事件总线 + Pipeline Phase 图 + 对象池）。

**为什么**：①结算与表现完全分离，纯逻辑引擎可 headless 测试（本环境核心需求之一）；②顺序确定、可复现，未来做存档回放/联机校验容易；③GDScript 下逐帧事件管线成本高、调试难，demo-1 证明简化链路已够用。④放弃实时管线换来一个代价：战斗过程中插入玩家交互（选目标）困难——已在引擎预留「交互点」扩展位（`next_action` 可返回等待输入的指令），未来需要时再加。

**考虑过的替代方案**：完整复刻 AbilityKit 触发链（TriggerPlan + Pipeline + GameplayTag + Modifier + Trace 五件套）。结论：对当前框架阶段属于过度设计，但其核心概念（事件→条件→动作单一链路、数据驱动）会以简化形式保留在 Trigger 系统里。
