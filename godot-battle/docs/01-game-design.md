## 一、战斗系统概述

《圣兽之王》是由 Vanillaware 开发、ATLUS 发行的战术 RPG。其核心战斗系统融合了**半即时战略**与**可视化编程**玩法。

### 核心设计理念

- **战前编程 = 核心玩法**：玩家在战斗前为角色配置技能条件和优先级，战斗中角色自动按设定行动
- **战斗自动进行**：双方队伍接触后进入自动回合制战斗，玩家无法干预
- **策略深度来源**：通过 "仅" 和 "优先" 两种条件类型的组合，实现复杂的 if-then 逻辑

### 战斗流程

```
战前配置 → 战场部署 → 队伍接触 → 自动回合战斗 → 结算
   ↑                                                    |
   └──────────────────────────────────────────────────────┘
```

## 二、角色属性系统

### 核心数值

| 属性 | 英文 | 说明 |
|------|------|------|
| HP | HP | 生命值 |
| 物理攻击 | Physical Attack (ATK) | 影响物理技能伤害 |
| 物理防御 | Physical Defense (DEF) | 减少物理伤害 |
| 魔法攻击 | Magic Attack (MATK) | 影响魔法技能伤害和治疗量 |
| 魔法防御 | Magic Defense (MDEF) | 减少魔法伤害 |
| 命中 | Hit/Accuracy | 影响攻击命中率 |
| 回避 | Evasion | 影响闪避概率 |
| 暴击率 | Critical Rate | 暴击概率 |
| 格挡率 | Guard Rate | 物理伤害格挡概率 |
| 行动速度 | Initiative/Speed | 决定行动顺序 |
| AP | Action Points (◆) | 主动技能消耗（红色） |
| PP | Passive Points (◆) | 被动技能消耗（蓝色） |

### 伤害计算核心公式

```
命中判定:
  命中率 = 命中 - 回避
  近战攻击非士兵单位 → 回避 × 2
  持盾单位使用掩护技能 / 眩晕 / 冰冻 → 回避 = 0
  必中(Sure Hit) → 无视命中率和回避

伤害计算:
  最终伤害 = 基础伤害 × (威力 / 100)
  威力 100 = 1倍，150 = 1.5倍，50 = 0.5倍

暴击:
  暴击时伤害 +50%（基础）
  多段攻击每段独立判定暴击

格挡（仅物理伤害）:
  无盾: 25% 格挡减伤率
  盾:   50% 格挡率 + 50% 减伤
  大盾: 75% 格挡率 + 75% 减伤
  技能格挡会覆盖装备格挡率
  格挡封印状态: 无法格挡

属性克制:
  克制时伤害 ×2
```

### 命中率对照表（示例）

| 命中 - 回避 | 实际命中率 |
|------------|-----------|
| ≥100 | 100% |
| 50 | ~84% |
| 0 | ~50% |
| -50 | ~16% |
| ≤-100 | 0% |

## 三、技能系统

### 技能分类

```
技能
├── 主动技能（红色）→ 消耗 AP
│   ├── 攻击技能（单体/一排/全体）
│   ├── 治疗技能
│   ├── 增益技能（Buff）
│   └── 减益技能（Debuff）
│
└── 被动技能（蓝色）→ 消耗 PP
    ├── 格挡/掩护
    ├── 追击/反击
    ├── 开场触发
    ├── 受到攻击时触发
    ├── 击败敌人时触发
    └── 回合结束时触发
```

### 技能数据结构

每个技能应包含以下字段：

```gdscript
{
    "id": "heavy_slash",
    "name": "重斩",
    "type": "active",          # active | passive
    "color": "red",            # red(AP) | blue(PP)
    "cost": 1,                 # AP或PP消耗
    "power": 150,              # 威力倍率
    "damage_type": "physical", # physical | magical | true
    "target": "single_enemy",  # single_enemy | row_enemy | all_enemy | self | single_ally | row_ally | all_ally
    "range": "front_row",      # front_row | back_row | any
    "effects": [],             # 附加效果列表
    "description": "对单个敌人造成150%物理伤害"
}
```

## 四、编程条件系统（核心玩法）

### 条件类型

游戏只有两种条件类型，通过组合实现复杂逻辑：

#### 1. 「仅」（限定条件 / Red Text）
- **含义**：条件必须满足，否则技能**跳过不执行**
- **用途**：限制技能只对特定目标使用
- **界面标识**：红色文字 "此技能在条件不满足时不会发动"

#### 2. 「优先」（优先条件 / Override）
- **含义**：优先选择符合条件的目标，没有则按默认逻辑
- **用途**：改变默认的"前排优先→就近原则"目标选择
- **界面标识**："覆盖默认目标选择规则"

### 目标条件列表

| 条件类别 | 条件示例 |
|---------|---------|
| **HP相关** | HP最低、HP最高、HP<50%、HP<25%、HP=100% |
| **防御相关** | 物理防御最低、魔法防御最低 |
| **兵种标签** | 步兵、骑兵、飞行、重甲、斥候、法师、治疗 |
| **位置** | 前排、后排、同列、同行 |
| **状态** | 中毒、灼烧、冰冻、眩晕、黑暗 |
| **属性** | 攻击最高、速度最快、回避最低 |
| **行动** | 第1次行动～第5次行动（仅类） |

### 三种组合方式

#### 组合一：优先 + 优先
```
执行顺序：
  第1步: 同时满足条件1+条件2的目标
  第2步: 仅满足条件2的目标
  第3步: 仅满足条件1的目标

特殊: 「优先前排」「优先后排」优先级最高，无论放在条件1还是条件2
```

#### 组合二：优先 + 仅（推荐最常用）
```
「仅」确定选择范围 → 「优先」在范围内排序
两个条件不冲突，无先后顺序问题

例: 「仅」步兵 + 「优先」HP最低
  → 在步兵中选择HP最低的攻击
  → 场上没有可攻击的步兵 → 技能跳过
```

#### 组合三：仅 + 仅
```
两个条件必须同时满足才触发（AND 逻辑）

例: 「仅」斥候 + 「仅」步兵
  → 只攻击同时拥有「斥候+步兵」标签的单位
  → 单独一个标签不触发
```

### 策略配置规则

1. **优先级从上到下**：优先级1的条件先检查，满足则执行，不满足则检查优先级2
2. **严格条件放上面**：条件越严格越靠前，避免被宽松条件"拦截"
3. **同一技能可多次配置**：用不同条件实现 OR 逻辑（如：优先1=打飞行，优先2=打重甲，优先3=默认）
4. **总共8个策略槽位**（主动+被动共享）
5. **被动技能有独立的优先级列表**

## 五、装备系统

### 装备槽

| 槽位 | 说明 |
|------|------|
| 武器 | 影响攻击力，部分武器附带技能 |
| 副手 | 盾牌（格挡）/ 副武器（双持，取最高值） |
| 饰品1 | 提供被动技能或属性加成 |
| 饰品2 | 提供被动技能或属性加成 |

### 装备数据结构

```gdscript
{
    "id": "flamberge",
    "name": "火焰之剑",
    "slot": "weapon",
    "stats": {
        "atk": 25,
        "crit_rate": 5
    },
    "granted_skill": "grisly_fire",  # 附带的技能ID
    "immunity": ["burn"],             # 免疫的状态
    "description": "攻击+25, 暴击率+5%, 附带「地狱火」技能，免疫灼烧"
}
```

### 装备效果类型

- 属性加成（攻击/防御/速度等）
- 附加技能（主动或被动）
- 状态免疫（免疫中毒/灼烧/冰冻等）
- AP/PP上限增加
- 经验值/金币加成
- 特殊效果（吸血、开场buff等）

## 六、战斗流程详解

### 回合流程

```
战斗开始
  ↓
[0] 开场被动技能触发（双方）
  ↓
[1] 按行动速度排序所有单位
  ↓
[2] 当前单位回合开始
  ↓
[3] 遍历主动技能策略列表（从优先级1开始）
  ├── 条件满足 → 消耗AP，释放技能 → 触发相关被动
  └── 条件不满足 → 检查下一条策略
  └── 所有策略都不满足 → 跳过回合（待命）
  ↓
[4] 下一个单位回合
  ↓
[5] 直到双方 AP 耗尽 或 一方全灭
  ↓
战斗结束
  ↓
判定: HP损失更多的一方失败
```

### 战斗嵌套规则

- 多段攻击每段独立判定命中/暴击/格挡
- 技能连锁上限为**2次**（防止无限循环）
- 掩护技能触发时，掩护者和被掩护者都不会触发"受到攻击"类被动
- 反击必须指向攻击者；追击指向被攻击的敌人

### 增益/减益叠加

- Buff/Debuff **可叠加**（+20%攻 + +15%攻 = +35%攻）
- 同类型正负可抵消（+50%攻 vs -50%攻 = 0%）
- 相同Buff通常不会刷新（除非技能明确说明）
