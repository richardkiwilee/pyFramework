# 地狱黑杰克（Hell Blackjack）设计文档

> 灵感来源：Steam《地狱黑杰克 Black Jacket》（Mi'pu'mi Games）。本项目是其"精髓玩法"的 1v1 对战复刻版，支持单机 AI、本地双人、可选联机对战。

## 1. 游戏精髓（本作的灵魂）

**每一张牌（花色 × 点数 的组合，共 52 种）的牌背都是不同的。** 牌堆顶牌的牌背对所有玩家可见，仔细观察牌背就能知道自己（和对手）下一张将抽到什么牌。

- 牌背信息是**对称公开**的：双方看到同一张牌背，谁认得编码谁占优势。
- 真正的隐藏信息只有牌堆内部顺序——需要靠记牌（弃牌堆可见）+ 读背来推断。
- 因此本作不是纯运气游戏，而是**观察力 + 记忆力 + 编码知识**的对决。

## 2. 核心规则

### 2.1 对局与筹码（钱即血量）

- 双方各 100 筹码，每回合底注 10（不足 10 则全押）。
- 赢家拿底池；**平局（push）各自退还底注**。
- 一方筹码归零 → 对局结束，另一方获胜。
- 单张 52 张牌堆，抽空后把弃牌堆洗回。

### 2.2 回合流程（状态机）

1. 双方手牌从空开始；每回合随机决定先手，之后交替。
2. 轮到你时二选一：
   - **要牌（Hit）**：抽走牌堆顶牌（其牌背在你抽之前就已被双方看到）。
   - **停牌（Stand）**：手牌锁定，至少须持有 1 张牌。
3. 手牌上限 **5 张**——5 张未爆自动停。
4. 双方都停牌后比大小；任一方**爆牌（>21）立即输**。

### 2.3 点数与胜负判定

- A = 1 或 11（自动取 ≤21 的最大值）；J/Q/K = 10；其余按面值。
- **自然黑杰克**：仅 2 张牌（A + 10 点牌）构成，压过一切非 BJ 的 21 点。
- 双方同点：比**单张最大牌**（A 最大，K>Q>J>10>…>2）；仍相同 → push 平分。
- 胜负优先级：一方爆牌输 > 自然 BJ 最大 > 点数接近 21 > 同点比单张最大 > push。

## 3. 牌背编码规范（52 种唯一牌背）

牌面尺寸 140×196（扑克比例 5:7），全部程序化绘制（无美术资源），所有牌背共享地狱风底纹，编码通道如下：

```
┌───────────────────────────────┐
│ ▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲ │  ← 上沿铆钉 = 点数（1..13 颗）
│┌───────────────────────────┐│
││ ╱╲╱╲╱╲  细网格底纹（无信息） ││
││   ╱◈╲                      ││
││  ◈ ◈ ◈  中央菱形徽章        ││
││   ╲◈╱   ◈= 花色符号         ││  ← 徽章色调 = 花色
││      徽章边框色 = 花色       ││
││        （低调融入底纹）      ││
│└───────────────────────────┘│
└───────────────────────────────┘
```

- **点数通道**：上沿铆钉（小圆点）数量 = 点数，A=1、2..10=2..10、J=11、Q=12、K=13。均匀分布在上沿，需借助放大镜点数。
- **花色通道（双重冗余）**：
  1. 中央菱形徽章的边框/填色色调：
     - ♠ 黑桃 = 暗青灰蓝，♥ 红桃 = 暗绯红，♦ 方块 = 暗琥珀，♣ 梅花 = 暗橄榄绿；
  2. 徽章中心的**花色符号**（程序化矢量绘制，非字体），色调略亮于徽章底。
- 四角花纹完全对称（不携带信息）。

### 3.1 观察模式（两档难度）

| 模式 | 放大镜提示 | 对照表（F1） |
|---|---|---|
| 新手模式 | 显示解码结果（如"♠7"） | 随时可开 |
| 地狱模式 | 仅原始放大，无提示 | 隐藏 |

对照表列出 52 张牌背及含义，供学习记忆；地狱模式考验真记忆。

## 4. 游戏模式

| 模式 | 说明 |
|---|---|
| 单机 vs AI | 简单 AI（不读牌背，≤16 就抽）/ 困难 AI（完美读背 + 记牌 + 评估对手手牌） |
| 本地双人 | 同屏轮流操作，牌背对双方公平公开 |
| 联机对战（可选） | ENet 直连：一方建主机（端口），另一方按 IP:端口加入；主机权威 |

## 5. UI 设计

- **主菜单**：标题 + 模式选择（单机 / 本地双人 / 联机-建主机 / 联机-加入，后两者含端口/IP 输入）+ 难度选择（新手/地狱）。
- **牌桌**（1280×720，Control 布局，暗色主题）：
  - 顶部：对手手牌扇面 + 筹码/状态；
  - 中部：**牌堆（顶牌牌背可见）** + 弃牌堆 + 底池 + 回合指示器；悬停牌堆显示 ×3 放大镜（新手模式附解码文字）；
  - 底部：玩家手牌扇面 + 筹码 + 操作按钮（要牌/停牌，非己方回合禁用）；
  - 右上：对局信息（回合数、战绩）；F1 切换对照表覆盖层；结算横幅（胜/负/push + 底池转移）。
- 复用 fullver-1 的 `UITheme`（SystemFont 微软雅黑链 + 面板/按钮样式工厂），牌面与牌背全部程序化绘制。

## 6. 联机协议（ENet，主机权威）

- `ENetMultiplayerPeer`：主机 `create_server(port, 1)`，客户端 `create_client(ip, port)`。仅 2 人，回合制，流量极低。
- **主机权威**：主机持有牌堆/牌局状态机，客户端只发意图。
- 客户端 → 主机：`rpc_action(action: String)`（"hit" | "stand"），主机校验回合归属。
- 主机 → 双方：`rpc_state(snapshot: Dictionary)` 全量快照广播：
  `{phase, turn, hands, top:{suit,rank}|null, deck_count, discard, chips, pot, result, winner}`。
  - `top` 只含牌堆顶牌（用于渲染牌背）——这正是玩家肉眼能看到的等价信息，不泄露牌堆内序。
- 断线/退出 → 存活方直接获胜（简单处理，无重连）。

## 7. 技术架构

```
black-joker/
  project.godot          # 主场景 main_menu.tscn；autoload: UITheme；警告视为错误
  scenes/  main_menu.tscn / table.tscn
  scripts/
    autoload/ui_theme.gd      # 移植 fullver-1 版本（调色板/面板/按钮/label 工厂）
    core/cards.gd             # CardData（suit/rank/面值）、Hand 点数计算（软硬 A/爆牌/BJ）
    core/deck.gd              # 52 张、洗牌（种子 RNG）、抽空洗回弃牌堆
    core/round.gd             # RoundEngine 纯逻辑状态机（回合/胜负/底池结算）
    core/match.gd             # 对局级：筹码、连局、先手轮换、对局结束
    core/back_drawer.gd       # 52 种牌背程序化绘制 + 编码/解码 + 纹理缓存
    ai/ai_player.gd           # 简单/困难 AI（纯函数，可测）
    net/net_game.gd           # ENet 主机/客户端封装 + RPC 协议
    ui/main_menu.gd / ui/table.gd / ui/card_view.gd / ui/magnifier.gd / ui/reference_sheet.gd
  tests/
    test_runner.gd(+.tscn)    # 自写极简 runner：扫描目录、push_error 记失败、退出码
    unit/test_cards.gd  test_deck.gd  test_round.gd  test_backs.gd  test_net.gd
```

- **核心逻辑全部是纯 RefCounted 类**（不依赖场景树），headless 可测。
- 不引入 zfoo（仓库内只有其客户端框架且无 Java 服务器；联机走 Godot 内置 ENet 更自洽）。
- 牌面/牌背全部程序化绘制（`_draw()`），花色符号为矢量图形（不依赖字体字形覆盖）。

## 8. 测试与验证策略

- **单元测试**（headless，自写 runner，退出码 0=通过）：
  - cards：软硬 A、最佳点数、爆牌、自然 BJ 判定、5 张上限；
  - deck：52 张唯一、种子洗牌可复现、抽空洗回；
  - round：脚本化 hit/stand 序列 → 胜负/底池断言（爆牌、push、BJ 压 21、同点比单张）；
  - backs：52 种（花色,点数）→ 绘制参数解码恒等 + 52 张渲染图两两像素不同；
  - net：同进程内 ENet 回环（双 MultiplayerAPI 上下文）跑完整一局脚本化对战。
- **截图验证**（窗口模式 + PIL 像素断言，按本仓库既定工作流）：
  - 牌桌渲染正确；两张不同顶牌 → 牌堆区域像素不同（证明牌背确实可区分）；
  - 悬停触发放大镜；F1 对照表可见；结算横幅出现。测完删临时驱动与 `_shots/`。

## 9. 范围外（有意不做）

- Roguelite 卡组构筑/神器/觉醒/花色技能体系（原作的大框架，本作只取读牌背精髓）。
- 断线重连、观战、大厅匹配、账号系统。
- 反作弊（牌背本就公开可读，无额外泄露面）。
