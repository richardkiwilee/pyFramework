## 1. 概述与通过标准

TheGreatConquest 是一款 4X 回合制策略游戏，在一张有固定线路连线的大地图上进行。设计把地图移动简化为"跳（Hop）"，把战略重心从"如何在地图上移动"转移到"何时、向哪里用兵"。

**核心循环**：经济 → 招募 → 移动 → 战斗 → 占领 → 夺首都 → 胜负。

**通过标准**：
- 能跑完一局：夺敌方首都且己方首都不丢为胜；首都被破即出局，其所有部队与单位立即解散，不设回合上限。
- 验证架构可行：数据驱动效果、统一修正管道、逻辑/交互分离、FSM、mod 层叠覆盖。

**胜负**：每阵营开局拥有唯一一个首都据点。某阵营首都被攻破后立即出局（`alive=False`），其所有部队解散、所有单位与装备释放、据点释放。不存在双方互夺首都的僵局。仅一个阵营存活时该阵营获胜。

## 2. 架构分层与代码结构

三层分离，Godot 实现须保持：

| 层 | 职责 | Python 原型位置 | 约束 |
|----|------|----------------|------|
| **框架层** | 渲染、输入抽象、场景栈、键提示栏 | `pyconsole/` | 可复用、可独立演进；游戏特定逻辑不得渗入；扩展限于通用能力（如 `hints_row`、`on_return`） |
| **业务层** | 纯游戏逻辑，无 IO | `pydemo/game/` | 纯逻辑、无 IO、不依赖任何界面；所有状态以字符串 id 互连，可直接 JSON 序列化 |
| **交互层** | 用框架的渲染/输入抽象，调用业务层逻辑，结果以日志/状态反馈 | `pydemo/tui/` | 桥接二者，不持有游戏规则 |

**动作常量分两处，不可混用**：框架导航动作在 `pyconsole.core.actions`（`UP/DOWN/LEFT/RIGHT/SELECT/CONFIRM/BACKSPACE/SCROLL_UP/SCROLL_DOWN/BACK` 等），游戏专属动作在 `pydemo.tui.actions`（`open_tech`/`open_culture`/`open_wiki`/`open_stronghold`/`open_army`/`open_recruit`/`open_unit`/`open_recruit_unit`/`open_stronghold_overview`/`open_inventory`/`open_map`/`end_turn`/`new_army`/`filter_1..4` 等）。

**可替换性**：语言、美术资源、按键绑定在设计上预留接口（动作名抽象、主题色集中、数据 JSON 化）。

**项目结构（pydemo）**：
```
pydemo/
├── game/        # 逻辑类（纯逻辑无 IO）
├── data/        # 声明式资源定义（JSON）
├── mods/        # mod 层叠覆盖
├── cli/         # scenario.py（剧本构建）
├── tui/         # 交互层（场景、控制器、FSM）
└── saves/       # 存档（save001.dat）
```

## 3. 回合与驱动循环

- **1 Turn = 1 Day**，顺序回合制：玩家先完成操作并点"下一回合"，其后 AI 阵营按固定顺序依次行动（即便操作可瞬间结算仍按序进行）。所有阵营行动完毕后回合结束，统一推进时间与月相，进入下一回合。
- 当前行动阵营可操作其所有部队与据点。
- **回合开始（`start_turn(faction)`）执行顺序**（见 §24）：
  1. `_tick_standby`：推进该阵营待命池所有单位冷却（cooldown -1，floor 0）。
  2. `reset_turn`：重置该阵营所有资源的本回合 delta（清空净变动记录），清空资源投影。
  3. `tick_economy`：建筑产出 → 扣维护费 → 据点补给补充 → 野外消耗/回血 → 据点回血。
  4. 招募池刷新：每 14 天刷新每据点招募池（见 §12）。
  5. `_dispatch_building_turn_events`：遍历该阵营所有己方据点建筑，触发 `on_turn` 事件（如锻造屋 forge_drop）。
  6. `maybe_trigger_event`：40% 概率为玩家阵营触发随机事件（仅玩家）。
- **回合结束（`end_turn_advance`）**：推进日历 1 天（`calendar.advance()`，推进昼夜与月相），重置所有部队 `has_acted_this_turn`。
- **结束回合键（T）**：执行 AI 行动 → 时间推进 → 重置行动标记 → 判定胜负 → 进入玩家回合。若游戏结束，PUSH 胜者消息框，下次按键返回主菜单。

## 4. 时间系统：昼夜与月相

两套独立时间周期，不耦合，共同驱动进攻/防守时机。

**常量**（`time_system.py`）：
```python
TIME_OF_DAY_STAGES = ["清晨", "白天", "黄昏", "夜晚", "深夜"]   # 5 阶段
TIME_OF_DAY_DAYS_PER_STAGE = 7      # 每阶段持续 7 天，永不复位
MOON_CYCLE_DAYS = 14                # 月相 14 天一周期
MOON_FULL_INDEX = 7                 # 满月在第 7 阶段（0 基索引）
```

**Calendar dataclass**（`day: int = 1`，1 基）：
- `advance()`：`day += 1`。
- `moon_phase_index()`：`(day - 1) % 14`，返回 0..13。
- `moon_phase_name()`：月相名。
- `mana_regen()`：`round(min(idx, 14 - idx) / 7 * 6)`，新月 +0 → 满月 +6 → 残月 +0 线性插值。
- `time_of_day_index()`：`((day - 1) // 7) % 5`，返回 0..4。
- `time_of_day_name()`：时段中文名。
- `describe()`：`"第 N 天 · 时段 · 月相(魔力恢复 +X)"`。

**昼夜修正（tod_bonus）**（`game.py collect_unit_mods` 内硬编码 dict）：

| 索引 | 时段 | 修正对象 | 属性 | 数值 | op |
|------|------|----------|------|------|----|
| 0 | 清晨 | melee（近战） | p_atk | +0.05 | pct |
| 1 | 白天 | ranged（远程） | p_atk | +0.05 | pct |
| 2 | 黄昏 | melee（近战） | p_atk | +0.05 | pct |
| 3 | 夜晚 | magic（魔法） | m_atk | +0.10 | pct |
| 4 | 深夜 | magic（魔法） | m_atk | +0.15 | pct |

**月相修正**：月相驱动魔力恢复（`moon_regen`），以 flat 加到 `mana_regen` 属性（如 `moon_mage` 技能 scale=1.0）。

> 由于月相 14 天 vs 昼夜每段 7 天且独立运行，同一天可能"满月+白天"或"满月+深夜"，玩家须同时盯住两个节奏。

## 5. 地图系统

`map_system.py`：地图由结点与固定连线组成，结点分两类。

### 5.1 数据模型

```python
@dataclass
class Building:
    id: str
    type_id: str          # 建筑定义 id（buildings.json 的 key）
    name: str             # 中文名
    produces: dict = {}   # 产出建筑: {资源: 数量}（landmark/recruit 为 {}）
    tier: str = ""        # 仅 landmark 用: "weak"/"medium"/"strong"

@dataclass
class Stronghold:
    id: str
    name: str
    size: int                 # 普通建筑槽数，整数 1~5（ADR-0006）
    owner: str | None = None  # 阵营 id
    is_capital: bool = False
    landmark: Building | None = None   # 标志性建筑，独立专用槽，不计入 size
    buildings: list[Building] = field(default_factory=list)  # 普通建筑列表
    stationed_army_id: str | None = None
    x: int = 0
    y: int = 0

    def slots(self) -> int: return self.size
    def free_slots(self) -> int: return self.size - len(self.buildings)
    def add_building(self, b: Building) -> bool:  # 校验 free_slots>0
    def tick_produce(self) -> dict[str, int]:  # 汇总所有建筑 produces

@dataclass
class MinorLocation:
    id: str
    name: str
    terrain: str              # terrain.json 的 key（plains/mountain/forest）
    x: int
    y: int

@dataclass
class GameMap:
    strongholds: dict[str, Stronghold]
    minors: dict[str, MinorLocation]
    adj: dict[str, list[str]]            # 邻接表，节点 id -> [邻居 id]

    def add_stronghold(...) / add_minor(...) / connect(a, b)  # 双向连边
    def node_name(node_id) / is_stronghold(node_id) / neighbors(node_id)
    def all_nodes() -> list[str]        # 据点 + 小地点
```

### 5.2 据点（Stronghold）

- 可被占领的结点，版图扩张核心。拥有 1 个标志性建筑（独立专用槽，不计入 `size` 槽位）+ `size` 个普通建筑槽位（`size` 整数 1~5）。
- 归属权取决于 `owner` 字段。
- 据点不再有"失能"状态，也不再生成驻军。

### 5.3 小地点（MinorLocation）

- 据点之间的结点，仅含地形数据，无标志性建筑，不可被占领。
- 部队停留消耗补给（见 §8 野外消耗）。
- 地形提供 flat 修正（`plains` 空、`mountain` p_def+5、`forest` eva+5）。

### 5.4 移动

- 以"跳（Hop）"为原子单位。每支部队每回合默认 1 跳（跨一个邻接结点）。技能可改基线（`map_skills` 原型为空，占位）。
- 移动与战斗内行动点（AP）是两套互不相关的资源。
- 目的地为距离 1 的邻接结点。若该处有敌方部队或敌方据点，标记 `[攻击]`，发起战斗。

### 5.5 补给

- 部队自身携带的独立资源（`Army.supply` / `supply_max`，默认 10/10），不属于全局资源。
- 小地点停留每回合消耗补给；耗尽后部队每个单位每回合扣固定比例生命（原型：5% HP）。
- 己方据点驻扎时每回合自动从阵营食物资源补充补给至上限（食物不足则只能补到食物允许的量）。
- 形成"食物产出 → 食物资源 → 据点补充 → 部队补给 → 野外消耗"闭环。

## 6. 据点与建筑

### 6.1 标志性建筑（Landmark）

- 据点归属权的载体，占独立专用槽（`Stronghold.landmark`），**不计入 `size` 槽位、不在 `buildings` 列表内**。
- 按档位区分（原型 3 档），仅决定给守方部队的 p_def 百分比 buff，不附带其他差异、不产出部队。
- 不会独立"摧毁"而悬空：随据点易主一并转为进攻方版本，或始终随据点存在。
- 数据来源：`buildings.json` 中 `kind=landmark` 的 3 条（`lm_weak`/`lm_medium`/`lm_strong`）。

**landmark 防御 buff 常量**（`game.py`）：
```python
LANDMARK_DEFENSE_BUFF = {"weak": 0.0, "medium": 0.10, "strong": 0.20}
```
战斗中 `_do_battle` 按 `sh.landmark.tier` 给守方部队 p_def 百分比加成（弱 0% / 中 10% / 强 20%）。

### 6.2 普通建筑

- 占据 `size` 槽位，资源产出与各类效果来源。占领后空槽即可建。
- **建造即时**（ADR-0006）：支付足额资源即立即建成，无建造回合、无"建造中"状态、不占英雄。
- 建造/拆除后立刻把下回合产出写入资源投影，面板"净变动"即时刷新（如 `食物:27(-3)` 建农场后立刻变 `27(+2)`）；投影由下回合 `reset_turn` 清空，真实产出由 `tick_economy` 记 delta，不重复计数。
- **拆除**：即时拆除、不退资源，刷新下回合产出投影。
- 按 `kind` 分三类：

| kind | 说明 | 门控 | 产出 |
|------|------|------|------|
| `produce` | 产出建筑，每回合固定产出资源 | **免门控**，无条件可建 | `produces` dict |
| `recruit` | 招募建筑，1:1 对应一种普通兵种 | 需 `requires` 列出的科技/文化已学 | 无产出 |
| `special` | 特殊建筑（如锻造屋） | 需 `requires` | 触发 `on_turn` 事件 |

### 6.3 建造门控（B7）

- **仅 `recruit` 与 `special` 类建筑**挂 `requires` 字段（科技/文化 id 列表），建造前须逐项校验该阵营 `tech_learned`/`culture_learned` 已含该 id，不满足则日志警告"需先研究 X"。
- **产出建筑（produce）免门控**，无条件可建。
- **兵种招募仅看建筑是否存在，不看科技**——门控只作用于建筑建造，不作用于兵种招募动作本身。

## 7. 占领机制

**无守直接占 + landmark 守方 buff**（ADR-0012，supersede ADR-0003）：

- 据点**无己方部队驻守**时：进攻方部队进入即**直接易主**（无战斗），标志性建筑转为进攻方版本。
- 据点**有己方部队驻守**时：进攻方须先击败守方部队（守方获标志性建筑 p_def 百分比 buff），胜方据守、据点易主。
- 中立据点开局**无驻军**，进入即占（靠 landmark buff 增加代价感）。
- **攻城战概念已移除**：据点战斗即普通战斗，无"驻军须另开攻城战打掉"的二段流程。

**`_capture_stronghold(sh, new_owner)`**：转 landmark 归属 + 据点归属，无额外部队生成。

## 8. 资源与经济

### 8.1 全局资源（11 种）

`economy.py` 常量：
```python
RESOURCE_TYPES = ["gold","food","wood","stone","iron","mana_stone",
                  "tech","culture","faith","luxury","decree"]
RESOURCE_CN = {
  "gold":"金币","food":"食物","wood":"木材","stone":"石材","iron":"铁矿",
  "mana_stone":"魔石","tech":"科技","culture":"文化","faith":"信仰",
  "luxury":"奢侈品","decree":"政令"
}
```

资源来源标记（`DeltaItem.source`）：
```python
SOURCE_BUILD="build"; SOURCE_MAINT="maint"; SOURCE_EVENT="event"
SOURCE_RECRUIT="recruit"; SOURCE_TRAIN="train"; SOURCE_SUPPLY="supply"
SOURCE_INIT="init"; SOURCE_UNKNOWN="unknown"
```

### 8.2 资源数据模型

```python
@dataclass
class DeltaItem:
    source: str          # SOURCE_* 之一
    value: int
    stronghold: str | None = None
    building: str | None = None

@dataclass
class Resource:
    kind: str
    amount: int = 0
    deltas: list[DeltaItem] = field(default_factory=list)
    _projected: int = 0   # 下回合预估产出（建造/拆除后立刻写入）

    def add(value, source, stronghold, building)   # 记 delta + 改 amount
    def add_projected(value) / clear_projected()
    def net()                # 本回合已结算净变动（sum deltas）
    def display_net()        # net() + _projected（面板显示用）
    def reset_turn()         # 清 deltas + clear_projected
    def output()             # "amount(+net)" 字符串

@dataclass
class Resources:
    amounts: dict[str, int]            # RESOURCE_TYPES -> amount
    _resources: dict[str, Resource]    # 内部 Resource 对象
    def get(kind) -> Resource
    def add(kind, value, source, stronghold, building)
    def can_afford(cost: dict) -> bool
    def pay(cost: dict) -> bool        # 逐资源扣，任一不足全失败
    def reset_turn()
    def resource(kind) -> Resource
```

### 8.3 资源展示

- 界面顶部以"现存(净变动)"形式显示每个资源，如 `金币:20(+1)`——括号前为现存总量，括号内为本回合已结算净变动 **+ 下回合预估产出**。
- 增量 >0 绿色、≤0 红色。建造/拆除后实时重算，不等回合结束。
- 每项净变动背后有明细细项（来源类型、数值、来源据点+建筑）。Python 原型不展示细项，迁移 Godot 时以悬停弹窗呈现。

### 8.4 资源消耗场景

每种资源在原型中至少一个消耗场景，避免"死资源"：
- 食物：维持补给与单位维护费。
- 木材/石材/铁矿：建造。
- 金币：招募、建造、交易。
- 魔石：招募魔法兵种。
- 信仰：招募僧侣。
- 科技/文化：学习研究项、建造门控。
- 奢侈品/政令：文化/经济加成与特权（产出建筑产出）。

### 8.5 tick_economy 执行顺序（`game.py`）

每阵营回合开始时，`tick_economy(faction)` 按序：
1. **建筑产出**（`SOURCE_BUILD`）：遍历该阵营所有据点的所有建筑，`tick_produce()` 汇总 `produces`，记入资源 delta。
2. **扣维护费**（`_deduct_maintenance`，`SOURCE_MAINT`）：逐单位按 `_maintenance_cost` 扣资源，允许部分扣；任一资源没扣足则标记该单位本回合 `starved`（断粮）。断粮单位本回合不回血（不掉血）。重置 `_trained_this_turn`。
3. **补给补充**（`SOURCE_SUPPLY`）：己方据点驻扎部队从食物资源补充补给至上限。
4. **野外消耗/回血**：小地点（minor node）部队补给 -1；若 `supply <= 0`，每个单位扣 5% HP，否则每个单位回 5% HP。
5. **据点回血**：己方据点内部队每个单位回 10% HP（跳过断粮单位）。

### 8.6 维护费与训练消耗

`_maintenance_cost(unit)`（默认）：
- 普通人类兵种：`{food: 1}`。
- 魔法兵种：追加 `{mana_stone: 1}`。
- 英雄：约 4 倍（如 `{food: 4}` 或 + mana_stone）。

`_train_cost(unit)`（默认）：
- `gold = recruit_cost // 2 + 5`（基于兵种 recruit_cost）。
- 普通人类：`{gold: ..., food: 5}`。
- 魔法兵种：追加 `{mana_stone: 1}`。

> 据点不再有免维护的驻军（驻军系统已废除，ADR-0012）。

### 11.4 关键规则

- **17 项属性**：occupy/hp/ap/pp/mana/speed/p_atk/m_atk/p_def/m_def/acc/eva/block/crit/luck/will/leadership。属性底层 double，每阶段向下取整（floor），玩家所见与战斗所用均为整数。
- **等级与经验**：1~99，升级所需经验 `5*level`（1→2 需 5、2→3 需 10……）。升级属性烘进 `base`（永久）。单位死亡时，击杀方所有存活单位各获得等同死亡单位等级的经验。
- **维护费**：见 §8.6。断粮只阻止回血、不掉血。
- **词条**：必选大类（melee/ranged/magic，至少其一可多选）+ 枚举小类（human/cavalry 等，可多选）。所有词条平级。词条 = 修正源输入 + 羁绊输入。
- **占用（Occupy）**：编入部队时消耗的领导力点数（普通 ≥15、英雄 ≥50）。九宫格恒占 1 格，与占用无关。占用不随等级增长，与领导力（增长）形成"老将带更多/更强兵"曲线。
- **生命恢复**：己方境内驻扎每回合 5%，据点内 10%（野外消耗见 §8.5）。**HP 跨战斗累积、开打不回满**（ADR-0004），单位带伤进入下场。
- **AP**：战斗内释主动技能，每场回满。与战略移动（Hop）无关。
- **PP**：战斗内释被动技能，每场回满。
- **Mana**：释魔法技能。**跨场累积、不每场回满**：进场仅按当前有效上限 clamp（月相/装备修正后），不补满；战斗外按月相每回合恢复（新月 +0、满月 +6 线性）。部分技能可同时要求 AP/PP 与 Mana。
- **装备**：最多 4 槽（0..3），按 def_id 库存计数模型（§15）。
- **特长（Perk）**：被动效果槽，来源事件（普通最多 4、英雄最多 8），钩子型 effect，不计入羁绊词条计数。
- **训练**：单位界面消耗 `train_cost` 直接 +5 XP，每回合每单位 1 次。训练需 `is_trainable`（己方据点内且该据点无敌方部队，或待命·可用）。训练不回血；升级时 HP 按比例保留。
- **意志生还（B3）**：见 §18.5。

## 14. 待命池（Standby）

`Faction.standby: dict[unit_id -> cooldown]`（ADR-0005）。阵营级单位候命池，取代原"聚贤庄"（B9 重命名）：全兵种通用、无位置，所有己方单位要么在某部队中，要么在待命。

**两态**：
- **可用**（cooldown <= 0）：可派遣到己方据点内部队、可训练。
- **不可用**（cooldown > 0）：下场后冷却中，暂不能上场。

**冷却规则**：
- `_tick_standby(faction)`：每回合开始推进该阵营所有待命单位 cooldown -1（floor 0）。
- 招募英雄/招普通兵后入待命·可用（cooldown=0）。
- 下场（`action_discharge`）按部队位置定冷却：**所属部队当前在己方据点内则冷却 0（立即可用），否则 5 回合**（`STANDBY_COOLDOWN=5`）。
- 上场（`action_deploy`）须部队位于己方据点（前线补员要回据点，不可空降）。
- 下场不限位置（任意位置均可下场）。

**`standby_available_ids()`**：返回 cooldown <= 0 的单位 id 列表。

## 15. 装备与仓库

装备按 **def_id 库存计数模型**（ADR-0009，supersede ADR-0007）。

### 15.3 装/卸位置限制（ADR-0009）

- 装/卸均要求单位所在部队在己方据点内——**待命单位可编辑**（无位置、默认安全），**野外部队不可穿戴/卸下**。不满足时日志提示"单位不在己方据点"，操作失败。
- 这是对早期"装备不受位置限制"设计的修正。

### 15.4 词条与技能重算

- 装备后单位词条重算 = 兵种本体 tag ∪ 当前装备 `tag_grant` 赋予的 tag（`_recompute_unit_tags`）。
- 装备经 `skill_grant` 效果赋予的技能写入 `Unit.granted_skills` 临时字段，装/卸时重算（`_recompute_granted_skills`，ADR-0008）。

### 15.5 装备获取渠道

1. **开局**：`scenario.py` 给每种装备定义各 3 件入库存（`add_artifact_stock`）。
2. **锻造屋**（B10，§6）：特殊建筑 `kind=special`，建造需 `forge_culture` 前置。建筑定义带 `on_turn="forge_drop"` 字段。每回合 `start_turn` 在 `tick_economy` 后、事件触发前新增 dispatch 阶段，遍历己方据点建筑触发对应 handler。锻造屋 5% 概率（`FORGE_DROP_CHANCE=0.05`）每回合随机产出一件装备，按稀有度加权抽取（`RARITY_WEIGHTS={"common":60,"uncommon":30,"rare":10}`），产出入阵营装备库存。
3. **卖出**：仓库界面 S 键，`action_sell_artifact` 按 def_id 卖 1 件库存，固定 +10 金币。

### 15.6 装备稀有度

`Artifact.rarity`：`common`/`uncommon`/`rare`，缺省 `common`。用于锻造屋抽取加权。

### 15.7 单位死亡/解散

`_release_artifacts(unit)` 只清装备槽（`unit.artifacts` 置空），**库存计数不变**（因卖出/装/卸才动库存，单位身上的槽只是占用记录）。

### 16.3 计算管道

```python
def compute_attribute(base, mods, attr, lo=None, hi=None) -> float:
    # 阶段1: base + flat，floor
    # 阶段2: * (1 + pct)，floor
    # 阶段3: clamp(lo, hi)
    # 每阶段向下取整，玩家可用整数反推公式
```

**固定顺序：flat → pct → clamp，每阶段 floor**。统一管道保证多源叠加无冲突。

### 16.4 修正源收集

`game.py collect_unit_mods(unit, army, calendar, terrain)`：
1. 月相 → `mana_regen` flat。
2. 昼夜 → `tod_bonus` dict（§4）pct。
3. 技能 perk → `collect_passive_modifiers`（§17）。
4. 装备 → `collect_passive_modifiers`。
5. 地形 → flat（`plains` 空、`mountain` p_def+5、`forest` eva+5）。

`collect_army_mods(army, calendar, terrain)`：在 `collect_unit_mods` 基础上加**羁绊**（synergy）修正。

## 17. 技能与效果系统

`effects.py`。技能以"数据描述 + 统一效果解释器"实现：每个技能是一份数据（效果类型 + 参数），由统一解释器执行。新增具体技能只改数据文件，不重编译；只有引入全新效果**类型**时才改解释器。

### 17.1 技能种类（kind）

```python
SKILL_ACTIVE = "active"; SKILL_PASSIVE = "passive"; SKILL_PERK = "perk"
SKILL_KINDS = [SKILL_ACTIVE, SKILL_PASSIVE, SKILL_PERK]
```

| kind | 管道 | 消耗 | 说明 |
|------|------|------|------|
| `active` | 策略表主动区，按行序检测释放 | AP（+Mana） | 战斗内玩家编排，`ap_damage`/`apply_status` |
| `passive` | 绑定发动时点，时点满足即触发 | PP | 每时点最多 1 单位响应，速度降序 |
| `perk` | 免费常驻，走统一修正管道 | 无 | 不占技能槽（ADR-0008） |

### 17.2 Effect 结构

```python
@dataclass
class Effect:
    effect_type: str          # flat_attr/pct_attr/tag_bonus/moon_regen/aura_flat/tag_grant/skill_grant/ap_damage/apply_status
    params: dict
    trigger: str = "passive"  # "active" | "passive"
    ap_cost: int = 0
    pp_cost: int = 0
    mana_cost: int = 0
    condition: dict | None = None
    trigger_point: str | None = None   # 被动时点

def build_skill_effects(raw) -> list[Effect]
def skill_kind(effects) -> str   # 默认 PERK
```

### 17.3 effect_type 一览

| effect_type | 说明 | 是否产出修正 |
|-------------|------|--------------|
| `flat_attr` | 固定加属性 | 是（flat） |
| `pct_attr` | 百分比加属性 | 是（pct） |
| `tag_bonus` | 拥有某 tag 时加属性 | 是（pct，条件=tag in owner_tags） |
| `moon_regen` | 按月相加魔力恢复 | 是（flat，mana_regen pct） |
| `aura_flat` | 队长时全队加属性 | 是（flat） |
| `tag_grant` | 赋予 tag | 否（改 Unit.tags） |
| `skill_grant` | 赋予技能 | 否（改 Unit.granted_skills） |
| `ap_damage` | 主动造成伤害 | 否（战斗内 execute_active_effect） |
| `apply_status` | 施加状态 | 否（战斗内） |

### 17.4 执行器

- `collect_passive_modifiers(...)`: flat_attr/pct_attr/tag_bonus/moon_regen/aura_flat 产出 Modifier；tag_grant/skill_grant 不产出修正。
- `apply_status_from_effect(...)`: 战斗内施加状态。
- `execute_active_effect(...)`: `ap_damage` → `resolve_strike`（统一命中/格挡/暴击管道），`apply_status` 施加状态；扣 AP/Mana。
- `execute_passive_effect(...)`: 被动时点触发执行。
- `active_cost(effect)` / `passive_pp_cost(effect)`。

## 18. 战斗系统

`battle.py`。战斗自动结算，玩家在战斗过程中不直接操作。

### 18.1 常量

```python
BATTLE_TICKS = 200              # 默认 200 Tick
ATB_THRESHOLD = 100.0          # 行动条阈值
ATB_RATE = 30.0                 # 行动条累加率（speed/ATB_RATE per tick）
                # speed 75 → +2.5/Tick，speed 60 → +2.0/Tick
BLOCK_EVA_ENABLED = True       # 格挡/闪避掷骰开关
BLOCK_DMG_FACTOR = 0.5         # 格挡伤害系数
```

### 18.2 数据模型

```python
@dataclass

@dataclass

    casualties: list

    evaded: bool
    crit: bool
```

### 18.3 战斗触发与频次

- 两军同结点触发。每支部队每回合**主动发起最多 1 场**战斗；被动防守不限次。
- 战斗自动结算（200 Tick）；未分胜负则防守方留守、进攻方退回出发结点。

### 18.4 run_battle 流程

```python
def run_battle(attacker_side, defender_side, strategies, skill_defs, rng,
               player_faction_id, block_eva_enabled=True) -> BattleResult:
    # 1. 初始化 eff_map（collect_army_mods）
    # 2. 初始化单位战斗状态: cur_ap/cur_pp = eff, mana clamp(0, eff上限), atb=0, alive=True, hp clamp, clear_statuses
    # 3. BATTLE_START 时点触发（一次性）
    # 4. 主循环（最多 BATTLE_TICKS 轮）:
    #    a. 每单位 atb += speed / ATB_RATE
    #    b. ready = [u for u if atb >= ATB_THRESHOLD]，按 (防守方优先, 前排优先) 排序
    #    c. frozen 单位: 跳过出手 + consume_on_self_attack
    #    d. 主动技能检测: active_rows 按行序，首个 _can_fire_active（AP+Mana 足、无目标型必要条件满足）的主动技能
    #       → execute_active_effect（ap_damage 走 resolve_strike，apply_status 施加）扣 AP/Mana
    #       → SELF_ATTACK_START/ALLY_ATTACKED_START 时点 → execute → ALLY_ATTACKED_END/SELF_ATTACK_END → consume
    #    e. 否则普通攻击: choose_target → resolve_strike（统一命中/格挡/暴击/意志管道）
    #    f. 检查 wiped
    # 5. BATTLE_END 时点 + clear_statuses（所有单位）
    # 6. 确定 occupier_side（一方全灭则对手占结点，否则 None）
```

### 18.5 resolve_strike（统一命中/格挡/闪避/暴击/意志管道）

```python
def resolve_strike(ctx, attacker, target, kind, flat_dmg=None) -> StrikeResult:
    # 1. 闪避掷骰: eva/100 概率 → dmg=0, evaded=True, 触发 ON_EVA
    # 2. 格挡掷骰: block/100 概率 → dmg *= BLOCK_DMG_FACTOR(0.5), blocked=True, 触发 ON_BLOCK
    # 3. 基础伤害: max(1, atk - def) 或 flat_dmg
    # 4. 暴击掷骰: crit/100 概率 → dmg *= 1.5, crit=True
    # 5. 意志生还（WILL_SURVIVAL_ENABLED）:
    #    new_hp = target.cur_hp - dmg
    #    if new_hp <= 0 and target.cur_hp > 1
    #       and target.id not in ctx.survived_this_battle
    #       and _unit_side(target) == ctx.player_faction_id:
    #       if ctx.rng.random() < (target.will / 100.0):
    #           dmg = target.cur_hp - 1   # 保留 1 HP
    #           ctx.survived_this_battle.add(target.id)
    # 6. consume_on_self_hit（命中分支）
    # 7. dispatch AFTER_PHYS / AFTER_MAGIC
    # 8. target.cur_hp -= dmg
```

**意志生还（B3）**：隐藏属性，**仅真人玩家有效**；单位 HP>1 且将致死时掷骰，`rng < will%` → 保留 1 HP；每单位每场战斗最多 1 次；覆盖所有致死伤害（普攻/ap_damage/被动追击统一走 `resolve_strike`，天然覆盖）。will 基准 5（即 5%），增长率普通兵 0.1、英雄 0.2（`make_unit`/`make_hero` 覆盖 unit_types.json 数据层）。AI 单位不触发。

### 18.6 战斗结局

- 200 Tick 走完且双方均未全灭：**不判胜负**——防守方不被驱离、留守原地，进攻方回到出发结点。
- 一方全灭：全灭方的对手占据该结点（`occupier_side`）。
- 进攻方需评估能否在 200 Tick 内解决战斗。

### 18.7 战斗后处理（`_do_battle`）

1. `collect_army_mods` 收集修正，landmark buff 给守方 p_def pct。
2. `run_battle(player_faction_id=self.player_id)`。
3. `_award_death_xp`：死亡单位等级 → XP 给击杀方存活单位。
4. 占领/首都陷落判定：
   - 攻击方胜且守方全灭 → `_capture_stronghold`（据点易主）。
   - 守方据点为首都且陷落 → `_on_capital_fallen`（`faction.alive=False`，释放所有单位/装备，解散军队，检查胜负）。
5. `_cleanup_wiped`：清理全灭部队。

### 18.8 三战斗资源（ADR-0008）

| 资源 | 跨场 | 回满 | 用途 |
|------|------|------|------|
| HP | 累积、不回满 | 否 | 生命，场间靠驻扎回血（野外 5%/据点 10%） |
| AP | 战斗内 | 每场回满 | 释主动技能 |
| PP | 战斗内 | 每场回满 | 释被动技能 |
| Mana | 跨场、不回满 | 进场仅 clamp 上限 | 释魔法技能，月相恢复 |

魔法闭环：魔石招魔法兵种 → 战斗内 Mana 释魔法技能 → 月相调 Mana 恢复。

## 19. 策略表与目标选择

`formation.py`。

### 19.1 策略表

```python
STRATEGY_ROW_CAP = 8

@dataclass
class StrategyRow:
    skill_id: str
    trigger_point: str | None = None
    necessary: list[dict] = []    # 必要条件（全满足才释放并筛合法目标）
    priority: list[dict] = []    # 优先条件（满足则偏好目标，不影响释放）

@dataclass
class UnitStrategy:
    unit_id: str
    active_rows: list[StrategyRow] = []     # 主动区
    passive_rows: list[StrategyRow] = []    # 被动区
    target_pref: str = "low_hp"            # 无条件退回时的目标偏好
    skill_order: list[str] = []
    hold_position: bool = False
    total_rows: int   # = len(active_rows) + len(passive_rows)

def validate_strategy(strategy) -> bool   # total_rows <= 8
```

- 战前为每单位预设策略表（≤8 槽，分主动区 + 被动区），按预设自动结算（ADR-0011）。
- 主动区按行序从上到下检测释放；被动区在触发时点响应。

### 19.2 条件类型（`triggers.py`）

**必要条件**（`NECESSARY_TYPES`，全满足才释放并筛合法目标）：
- `self_hp_le`：自身 HP% <= threshold
- `ally_avg_hp_le`：盟军平均 HP% <= threshold
- `row_count_ge`：某排存活数 >= threshold
- `enemy_has_frozen`：敌方有冰冻单位
- `target_pref_low_hp` / `target_pref_front` / `target_pref_random`：目标合法性偏好

**优先条件**（`PRIORITY_TYPES`，满足则偏好目标，不影响释放）：
- `pref_enemy_frozen` / `pref_enemy_debuffed` / `pref_low_hp` / `pref_front` / `pref_random`

`eval_necessary(condition, ctx, unit, target) -> bool`：必要条件求值（self_hp_le pct<=thr、ally_avg_hp_le、row_count_ge、enemy_has_frozen、target_pref_* 合法性）。
`priority_key(conditions, ctx, unit, target) -> tuple`：优先条件排序键（lower=preferred）。

### 19.3 目标选择（`choose_target_with_slots`）

1. 按兵种角色选目标池：近战 → 前排最前；远程/魔法 → 任意存活。
2. **必要条件过滤**目标池。
3. 池空 → 回退可达性池（不软锁）。
4. **优先条件稳定排序**。
5. 无条件 → 退回 `target_pref`（low_hp/front/random）。

### 19.4 默认策略（`default_strategy`）

- 近战 → front pref，其他 → low_hp。
- active 技能 → active_rows（带 target_pref necessary）。
- passive 技能 → passive_rows。
- perk 排除（不占策略槽）。

`build_default_formation`：为部队所有单位生成默认策略。

## 24. 回合执行顺序

### 24.1 start_turn(faction)

```

   3.1 建筑产出 (SOURCE_BUILD)
   3.2 _deduct_maintenance (SOURCE_MAINT) → starved 标记，重置 _trained_this_turn
   3.3 己方据点补给补充 (SOURCE_SUPPLY)
```

## 29. 交互层规格（场景与键位）

> 本节是 UI 实现契约。框架（`pyconsole`）负责渲染与输入抽象，业务层（`pydemo/game/`）负责逻辑，本节描述交互层。Python 原型为 100×30 TUI，Godot 实现可替换 UI/渲染/输入层但须保持场景栈与回值通道语义。

### 29.1 框架全局约定

- **动作名（action）**：按键抽象为动作字符串（`UP`/`CONFIRM`/`open_tech`），场景按 `event.action` 分支，与物理键解耦，便于改键。
- **场景栈（scene stack）**：界面以栈组织。打开子界面 = `PUSH` 压入新场景；返回 = `POP` 弹出。栈顶场景独占输入与渲染。
- **回值通道（on_return）**：子场景 `POP(value)` 携带回值；框架把 `value` 交付给弹回栈顶场景的 `on_return(value)`。`on_return` 可返回 `SceneResult` 让框架立即继续栈转换（如直接 `POP()` 弹出自身回上层，或 `PUSH(...)` 推入消息框）——返回 `NONE()`/`None` 则不再产生栈动作。`on_exit`（只清理）与 `on_return`（接收回值可触发跳转）职责分离。
- **键提示栏（hints_row）**：场景用类属性声明位置：`"bottom"`（默认，h-1 行）/`"top"`（第 0 行）/任意 int 行/`None`（框架不画，场景自管）。框架在 `render()` 后于该行调 `render_hints(buf, y, w)`。
- **实时百科**：任意游戏内场景按 H 进入模糊搜索百科，输入即筛选，无回车阻塞。
- **状态总览 overlay**：游戏内场景按住 Tab 显示"帝国总览"浮层；松开即消失。
- **全局日志栏**：游戏内子场景在 y=h-2 绘制统一日志栏（最近 3-4 条，` │ ` 分隔，普通=DIM、警告=WARN）。主场景日志在 y=h-1。

### 29.6 各场景操作细则

**主菜单**：仅 ↑↓/回车。继续游戏读 `save001.dat`（`Game.restore`）；开始游戏调 `new_game()` 构建剧本 PUSH 主场景；退出 `QUIT()`。ESC/Tab 在主菜单无效。

**游戏主场景**：
- y=0 可用按键操作，y=1 日历（`calendar.describe()`），y=2 资源+信念，y=3..h-2 地图拓扑，y=h-1 日志。
- 地图：据点 `◆名称 [N](归属)`（己方绿/敌方红/中立白，首都标"(都)"），小地点 `·名称 [N]`（仅有野战部队时显示）。`[N]` 为该节点驻守部队存活单位数（仅我方绿/仅敌方红/双方接触黄）。节点间 `─│╲╱`+拐角连线。即时更新（每帧从游戏状态现算）。
- T：结束本回合（AI 行动 → 时间推进 → 判定胜负）。
- ESC：PUSH 退出选单。
- Tab：帝国总览 overlay（60×16，阵营名/日历/据点部队英雄数/信念/11 资源/胜者）。

**退出选单**：继续（POP）/保存（`save()` 写 save001.dat + 消息框）/读取（`load()` 读 save001.dat，成功 POP 回游戏）/返回主菜单（`POP("to_menu")`，主场景 `on_return` 收到后直接 `POP()` 同帧回主菜单）。↑↓切换，回车/空格确认，ESC 关闭。

**科技树/文化树**：左右等宽分割。1234 筛选（全部/已学习/未学习/可学习）。左侧列表按状态着色（绿已学/白可学习/红锁定/黄资源不足）。回车学习（校验 prereqs ⊆ learned + can_afford，调 `action_learn_tech`/`action_learn_culture`）。空格切换左右焦点。右侧详情 ↑↓ 切跳转词条，回车 PUSH WikiScene({"query":词})。`[[词]]` 为跳转词条。

**据点一览（C）**：4 层嵌套窗口（W1 大地图据点/W2 单据点详情/W3 槽位操作/W4 候选）。→ 逐层进入，← 回退，回车等同 →。非己方据点可查看 W2 但不能操作（槽位与部队拒绝）。建造走 `action_build`（资源/槽位校验，支付即即时建成，刷新产出投影）；拆除走 `action_demolish`（即时拆除不退资源，刷新投影）。recruit/special 建筑需 requires 已学。建造即时故无"建造中"状态。面包屑显示层级路径。

**据点总览（V）**：表格纵览。1234 筛选（我方/敌方/中立/全部）。最左列据点名称（◆+归属色+首都标），次列标志建筑（中文名，按 tier 决定守方 buff），其后槽位列 1~5（三态：建筑名/空/X）。回车 PUSH StrongholdScene 预选到该据点。只读视图，编辑委托据点界面。

**部队一栏（A）**：3 窗口 + 九宫格单元格编辑。窗口随焦点是否进入九宫格单元格重排。123 筛选（我方/敌方/全部）。焦点三层 W1→W2→W3，→ 逐层进入、← 回退（W2→W3 例外：须 W2 选"编辑"按回车才进 W3 九宫格焦点）。W2 部队操作：移动/编辑/解散。移动模式：W3 列距离 1 邻接结点（敌方标 `[攻击]`），回车 `action_move_attack`。N 新建部队（仅 W1，阵营级待命·可用英雄任队长）。单元格模式：单位格→移动/下场/编辑装备；空格→上场（须部队在己方据点）。下场 `action_discharge`（冷却看部队位置），上场 `action_deploy`。解散 `disband_army`（直接丢弃单位，不进待命池）。编辑装备委托 UnitScene。

**单位一览（X）**：2 窗口（W1 单位列表/W2 单位详情）。跨部队全局花名册。↑↓ 选单位，空格/回车进详情。W2 详情：名称/词条/英雄/所属部队/位置、装备可编辑性提示（己方据点/待命=可编辑，野外=不可）、等级经验、生命、17 项属性（3 列）、维护费、训练消耗（或不可训练原因）、技能面板（名+kind+AP/PP/Mana 消耗+触发时点+逐 effect 描述，仅展示）、底部 5 按钮（训练+4 装备栏）。训练 `action_train`（+5 XP，每回合每单位 1 次，按钮置灰条件见 §11.4）。装备栏按 def_id 库存模型（满槽回车卸下 `action_unequip`，空槽回车进选择子模式 `action_equip`，装/卸须己方据点）。

**招募一览（Z，英雄）**：3 窗口对应招募池 3 名英雄。↑↓ 切换据点，←→ 选英雄，回车招募（`action_recruit_hero`，资源/信念校验）。成功留在本场景（被招募窗口置空，其余英雄原位保留），英雄进待命·可用。每据点独立池，每 14 天刷新 3 个。`offerings` 固定 3 槽（hero_def id 或 None），招募置 None 不压缩。

**招兵（Q，普通兵）**：单列列表，列出全部 5 种普通兵种（兵种名+对应招募建筑名+recruit_cost+可招状态）。解锁判定：阵营任一己方据点建成对应招募建筑即解锁（不必在建造据点）。可招状态：已解锁且资源够=可招（绿），资源不足=资源不足（黄），未建造=(未建造)（灰）。回车 `action_recruit_unit`（全局存在性+资源扣费），成功新单位进待命·可用 cooldown=0，留在本场景可连续招。无信念门槛。

**仓库（I）**：2 窗口（W1 装备列表按定义/W2 装备详情）。W1 每行"定义名 库{在库可用}/装{已装备}"，按 def_id 排序（含库存 0 的）。W2 库存/在库可用/已装备三项、归属列表、效果描述（含 rarity）。S 卖出（在库可用>0，`action_sell_artifact` +10 金币），X 卸下（已装备>0，找一件装备该定义的单位卸其槽，须该单位在己方据点）。S/X 在 W1 焦点时生效，通过读字符动作拦截不冒泡。

**地图一览（M）**：只读全屏拓扑图，同主场景内嵌渲染。ESC 返回。

**百科（H）**：实时模糊搜索（中文子串匹配）。顶部搜索框，左侧结果列表，右侧详情。↑↓ 切换，Backspace 回退，PgUp/PgDn 滚动，ESC 返回。可经 `PUSH WikiScene({"query":词})` 预填。数据来自 `pydemo/data/tui_wiki.json`，只读参考层。

**待命池**：只读表格（单位/词条/状态），↑↓ 切换，ESC 返回。**暂未挂接入口**（无绑定键），招募/下场单位在此候命，上场走部队界面单元格"上场"。`allow_status_overlay=True`。
