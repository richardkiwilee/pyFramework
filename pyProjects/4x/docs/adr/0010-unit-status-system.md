# 单位状态系统

引入离散的单位状态(Status),与连续数值的修正管道分离。状态类型为枚举集(如冻结/冰封/减益等,带分类标签与默认持续回合),`Unit.statuses` 存当前状态及其剩余回合(与堆叠层数)。状态在攻击/回合推进时倒计时,到 0 解除。状态是技能效果(如"冰封"对敌方施加冻结)与策略表条件(如"优先处于冻结状态的敌方")的输入。

**Considered Options**:曾考虑把状态塞进修正管道(如 `frozen` 当作一个 `pct_attr speed -100%` 的修正项)。但状态是**离散标签 + 计时 + 解除条件**(冻结=不能行动且到时解除、减益=分类可被"优先处于减益状态的敌方"匹配),不是连续数值增减;混进修正管道后无法表达"是否处于冻结"这种布尔判定,也无法承载堆叠与分类标签。故状态单列为独立系统,与修正管道正交:修正是连续数值增减(走 `compute_attribute`),状态是离散标签 + 计时(走 `Unit.statuses` tick)。代价:效果解释器需在施加/推进/解除三处处理状态,而非全部经修正管道统一。

**Consequences**:本期(批次1·数据模型层)只在 `Unit` 上加 `statuses` 字段与状态类型枚举占位;状态的施加(tick 推进、到 0 解除)与作为条件/效果输入的引擎逻辑属批次2,本期不接。状态枚举类型集可随技能需要扩展(同触发时点枚举)。
