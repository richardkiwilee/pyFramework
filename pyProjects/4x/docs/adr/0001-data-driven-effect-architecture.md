# 数据驱动的技能/被动效果架构

技能与被动效果以数据描述(效果类型 + 参数) + 一个统一的效果解释器实现,而非为每个效果写一个 OOP 子类(策略模式 + 工厂)。新增具体技能/被动只改数据文件、不重编译;只有引入新的效果**类型**时才改解释器代码。

README 明确要求"设计代码结构时需要考虑能够轻松新增效果而不需要重新编译",且 mod 需能"添加英雄、添加建筑等"。数据驱动是这两点的共同前提。考虑过的替代是 Effect 子类 + 工厂注册(表达力更强、更类型安全),但每次新增效果都要写类并重编译,直接违背 README 的核心约束,故不取。代价:效果类型集合由解释器枚举固定,mod 不能在不动代码的前提下引入全新效果类型——这与"只增内容、不改流程"的 mod 边界一致。
