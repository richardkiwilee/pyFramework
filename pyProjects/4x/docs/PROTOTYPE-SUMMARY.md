# 原型设计总结（Python Demo / pydemo）

本文件是 `grill-with-docs` 头脑风暴的结晶,记录 Python 原型要实现什么、为什么。术语定义见 [CONTEXT.md](../CONTEXT.md),不可逆架构决策见 [docs/adr/](../docs/adr/)。本文不复述术语,只记录原型落地的范围与默认值。

## 目标

端到端薄片:1 阵营玩家 + 1 阵营 AI,在一张 3–4 据点的小地图上跑通"经济 → 招募 → 移动 → 战斗 → 占领 → 夺首都 → 胜负"完整一局,并验证关键架构点。UI 不是重点,纯 Python 控制台交互。

## 通过标准

- 能跑完一局(夺首都且己方首都不丢为胜,首都被破即出局,所有部队立即解散;不设回合上限)
- 验证架构可行:数据驱动效果、统一修正管道、逻辑/交互分离、FSM、mod 层叠覆盖

## 驱动循环

- 1 Turn = 1 Day,顺序回合制:玩家行动 → 点击"下一回合" → AI 按序行动 → 回合结束推进时间与月相
- 时间推进:昼夜段每 7 天切换(清晨/白天/黄昏/夜晚/深夜,永不复位);月相 14 天周期(14 阶段,新月+0→满月+6 线性插值,满 14 天重启)。两者独立运行
- 回合开始随机触发事件(流民/商队),选择调整信念或资源

## 地图

- 拓扑:两首都夹中立据点,双路径连接(主路 + 迂回),据点间有小地点
- 3–4 据点:每阵营 1 首都 + 1–2 中立据点;据点 `size` 为整数 1~5,直接给出普通建筑槽数,不映射占领难度(ADR-0006)
- 小地点:仅含地形(平原/山地/森林 3 种),无标志建筑,不可占领;停留消耗补给
- 移动:每回合默认 1 Hop(跨一个邻接结点),技能可改基线
- 补给:部队携带量,小地点每回合消耗,耗尽则每单位每回合扣固定比例生命;己方据点驻扎时自动从食物资源补至上限

## 据点与占领

- 据点 = 1 标志建筑 + N 普通建筑槽(规模决定)。归属取决于标志建筑;据点不再有"失能"状态,驻军被全灭、进攻方进入据点即易主,标志建筑转进攻方版本
- 3 种标志建筑 = 3 档驻军强度(弱/中/强),仅决定驻军强度
- 据点驻军:标志建筑提供的真实完整部队,编队由建筑定义、玩家不可改;未全灭时每回合回血补兵,被全灭即易主
- 攻城战:据点有玩家驻军时,进攻方先与玩家驻军交战(玩家驻军获小幅 buff,由标志建筑档位决定);进攻方该回合已开战,即便玩家驻军被全灭也本回合不得进入据点,须由其他部队另开攻城战打驻军。据点无玩家驻军时直接打驻军
- 占领:驻军被全灭即易主,标志建筑转进攻方版本,无建造时间。中立据点也有较弱驻军,机制统一

## 资源与经济

- 11 种全局资源全接入:金币、食物、木材、石材、铁矿、魔石、科技、文化、信仰、奢侈品、政令
- 每种资源 1 个产出建筑,固定产出/回合(如农场 +5 食物);占领后空槽可建,建造耗资源,**支付足额即即时建成**(无建造回合,ADR-0006,不占英雄)。建造/拆除后立刻把下回合产出写入资源投影,面板"净变动"即时刷新(如 27(-3) 食物建农场后立刻变 (+2));投影由下回合 reset_turn 清空,真实产出由 tick_economy 记 delta,不重复计数
- 领主:英雄可被指派为据点领主,与队长互斥(任领主不能带兵出征)。原设计为该据点建造减回合,**建造即时后该效果失效,领主职责待重定义**(ADR-0006,占位保留)
- 资源消耗场景(每种至少 1 个):招募/建造/维持门槛
- 双门槛验证:英雄招募 = 资源消耗 + 信念门槛(Belief 某维 ≥ 某值,不是信仰资源)
- 信仰资源:招募僧侣时替代金币(信仰轴与魔法轴在僧侣交汇)

## 信念与事件

- 3 维信念:道德、功利、自由,每维 [-100, +100],以 0 为中心,维度独立互不制约
- 增减源:建筑效果、事件选择、任务完成。事件典型 ±5/±10
- 2 个示例事件(回合开始随机触发):
  - 流民 → 安置(道德+,耗食物)/驱赶(功利+,不耗)
  - 商队 → 高税(功利+,金币+)/免税(自由+,文化+)

## 单位与部队

- 原型兵种表(均带"人类"小类):
  - 步兵 {近战, 人类}(金币)
  - 骑兵 {近战, 人类, 骑兵}(金币)
  - 弓兵 {远程, 人类}(金币 + 木材)
  - 魔法师 {魔法, 人类}(魔石)
  - 僧侣 {魔法, 人类}(信仰)
- 英雄单位:精心设计,有被动/技能;招募耗资源 + 信念门槛;可任队长或一般单位编入他队
- 词条体系:必选大类(近战/远程/魔法,至少其一,可多选)+ 枚举小类(人类/骑兵等,可多选),全部平级
- 部队 3x3 九宫格,前/中/后三排;**队长领导力(Leadership)决定部队可承载的占用(Occupy)总和**;部队必须始终有队长,队长离队须从本部队其他英雄或阵营级待命·可用英雄指派接任,否则解散
- 兵种词条 = 修正源 + Synergy 输入;Synergy 按词条数量分档,奖励只给本人不共享
- 英雄调度:招募/下场后进入阵营级**待命池(Standby)**(取代聚贤庄,ADR-0005);待命·可用可派遣到己方据点内部队或训练,待命·不可用为下场后冷却中。上场须部队在己方据点,下场不限位置;**下场冷却看部队位置——部队在己方据点内则冷却 0(立即可用),否则 5 回合**
- 单位成长:等级 1~99,升级所需经验为公差 5 的等差数列;升级属性烘进 base,每阶段 floor;**HP 跨战斗累积不回满**(ADR-0004),场间仅靠驻扎回血(野外 5%/据点 10%)。训练(单位界面 X)每次 +5 XP、每回合每单位 1 次,升级时 HP 按比例保留
- 维护费:单位每回合消耗全局资源(普通人类兵种 {food:1},魔法兵种追加魔石,英雄约 4 倍),驻军免维护;断粮只阻止回血、不掉血
- 特长(Perk):事件获得的被动效果槽(普通单位最多 4、英雄最多 8),钩子型 effect,不计入 Synergy
- 神器:2 个示例——1 个加属性(+10 物攻),1 个附带词条(装备后获"骑兵"词条,助凑 Synergy);单位最多 4 神器槽
- 装备 def_id 库存计数模型(ADR-0009,supersede ADR-0007):`Faction.inventory = dict[def_id → 库存数]`,无件级实例、无库存上限、无卸下冷却。`Unit.artifacts` 存 def_id 列表(槽位 0..3,最多 4),已装备由反查所有己方单位 `artifacts` 推导(`equipped_count` / `available_count`)。卖出按 def_id 减 1 库存(+10 金币)。装/卸受位置限制:单位所在部队须在己方据点内(待命单位可编辑,驻军/野外不可),无 200 件上限、无 5 回合卸下冷却。单位死亡/解散时 `_release_artifacts` 只清槽(库存计数不变)。装备亦可经 `skill_grant` 效果赋予技能(写入 `Unit.granted_skills`,装/卸重算)。开局 scenario.py 给每种装备定义各 3 件入库存(`add_artifact_stock`)
- 仓库界面(I):左右两窗口,左侧列全部装备**定义**(每行"定义名  库{在库可用}/装{已装备}",有被装备件用 ACCENT2),右侧显示选中定义的库存/在库/已装备三项、归属列表、效果描述。S 卖出(在库可用 > 0,按 def_id 减 1 库存)/X 卸下(已装备 > 0,找一件装备该定义的单位卸其槽,要求该单位在己方据点)
- 技能/被动:5+ 个示例(词条加成、月相修正、光环、AP 主动技能等),数据驱动 + 统一解释器;技能 kind 三值——active(主动耗 AP,策略表)/passive(被动耗 PP,发动时点)/perk(免费常驻走修正管道,不占技能槽,ADR-0008)

## 战斗

- 触发:两军同结点;每回合主动发起最多 1 场,被动防守不限次
- 结算:Tick 驱动,默认 200 Tick;每 Tick 各单位行动条按速度累加(速度 75 = +0.75/Tick),达 100 出手;同 Tick 多人达 100 时防守方优先、前排优先
- 结局:200 Tick 走完不判胜负,防守方留守原地、进攻方回出发结点;一方全灭则另一方占结点
- 九宫格:行列决定射程与掩拦——近战打同列或邻列前排,远程/魔法可越排,前排掩护同列后排
- 战斗策略:战前为每单位预设策略表(≤8 槽,分主动区+被动区,主动按行序从上到下检测释放、被动在触发时点响应),按预设自动结算(ADR-0011)
- 策略表条件:必要(全满足才释放并筛合法目标)+ 优先(满足则偏好目标,不影响释放)两型,结构化 dict 编码(如 `{"type":"self_hp_le","threshold":50}`);必要先过滤、优先后排序;池空回退可达性池不软锁
- 触发时点(ADR-0011):10 个枚举——battle_start / battle_end(一次性)、self_attack_start/end(攻击者出手前后)、ally_attacked_start/end(被攻击方响应前后)、on_block / on_eva(格挡/闪避成功时)、after_phys / after_magic(受物理/魔法攻击后)。按时点各自计,每时点最多 1 单位响应,速度降序、判满足即扣 PP(响应前)
- 状态系统(ADR-0010):消费模型(无 tick 计时),三型消费方式——整场持续 / 自身攻击消耗层 / 自身受击消耗层;重施加取 max 不叠加;battle_end 清场(状态不跨场);状态作为策略表条件输入(enemy_has_frozen / pref_enemy_frozen 等)
- 命中/格挡/闪避/暴击掷骰:统一管道(普通攻击与 ap_damage 共用),命中后判闪避(→伤害 0,触发 on_eva)、格挡(→伤害减半,触发 on_block)、暴击(→伤害 ×1.5);模块开关 BLOCK_EVA_ENABLED 可一键关闭(恒命中无格挡/闪避)
- RNG 注入:run_battle 接 rng 参数,战斗脱离全局 random.seed,便于测试定种子
- 三战斗资源(ADR-0008):HP 跨场累积不回满;**AP**(行动点)战斗内释主动技能,每场回满;**PP**(被动点)战斗内释被动技能,每场回满;**Mana**(魔力点)释魔法技能,**跨场不回满**(进场只按当前有效上限 clamp,月相恢复,新月+0→满月+6 线性)。部分技能可同时要求 AP/PP 与 Mana
- 魔法闭环:魔石招魔法兵种 → 战斗内 Mana 释魔法技能 → 月相调 Mana 恢复

## AI

贪心启发式,5 条优先级规则:
1. 首都不受威胁时补经济、建产出建筑
2. 凑信念/资源招英雄扩军
3. 遇中立据点弱驻军则夺
4. 遇敌方主力弱势则攻
5. 有机会夺敌首都优先

## mod

- 原型验证层叠覆盖:基础定义文件 + 1 个 mod 文件,验证 mod 能覆盖某英雄数值、追加新英雄
- 形式:声明式数据文件 + 同名覆盖,不引入脚本/补丁 DSL
- 边界:只增内容(英雄/建筑/兵种/技能/修正/事件/资源定义),不改主流程

## 项目结构（pydemo）

```
python-demo/pydemo/
├── game/        # 逻辑类:map/stronghold/army/battle/resource/modifier/event/hero/...
├── data/        # 声明式资源定义(英雄/建筑/兵种/技能/事件/地图)
├── mods/        # mod 层叠覆盖
├── cli/         # FSM + 控制台交互/渲染
└── main.py
```

- 控制台输出中文,代码标识符英文;数据定义中文可读值 + 英文键
- 逻辑与交互分离;一个功能点一个类;按键逻辑用 FSM 调类函数;预留语言/美术/按键绑定接口
- 装备仓库落地:`game/` 含装备 def_id 库存计数与仓库逻辑(`add_artifact_stock` / `artifact_def_of` / `equipped_count` / `available_count` / `action_equip` / `action_unequip` / `action_sell_artifact` / `_release_artifacts`);`tui/scenes/inventory.py` 为仓库场景(键 I)
- 战斗引擎落地:`game/triggers.py`(TriggerPoint/StatusType/StatusConsume/ConditionType 枚举 + 状态消费函数)、`game/formation.py`(8 槽两区策略表 + 条件求值 + 带槽位选目标)、`game/effects.py`(主动/被动执行器)、`game/battle.py`(BattleContext/resolve_strike 统一管道/主动执行/被动调度 dispatch_trigger/状态消费/冻结跳过/RNG 注入);`tui/scenes/unit.py` W2 技能描述面板
- 单测:`pyconsole/tests`(149 测)框架/渲染/效果;`pydemo/tests/test_battle_engine.py`(27 测)战斗引擎端到端。`py smoke_test.py` 为对局冒烟(exit 0 = 过)
- 技术栈:纯 Python 标准库,无第三方依赖
