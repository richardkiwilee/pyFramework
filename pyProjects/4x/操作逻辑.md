# 操作逻辑说明

本文档是 TheGreatConquest（TUI 演示版）的**操作交互规格**。它定义了玩家在终端界面中可执行的所有交互选项、各场景的有限状态机，以及视觉状态（焦点、颜色、筛选）的语义。它是 UI 实现的契约：框架（`pyconsole`）负责渲染与输入抽象，业务层（`pydemo/game/`）负责游戏逻辑，本文档描述两者之间的交互层。

> 本文只描述"怎么操作"，不描述游戏机制本身。游戏总设计见 [README.md](README.md)，术语定义见 [CONTEXT.md](CONTEXT.md)。本文档内的机制说明仅作为操作的背景，用以说明某个交互为何如此设计。

---

## 0. 框架与全局约定

### 0.1 运行环境

- 终端固定为 **100 列 × 30 行**（`SCREEN_W=100, SCREEN_H=30`）。
- 零第三方依赖，仅使用 Python 标准库（`msvcrt` / `ctypes` / `json` / `unicodedata` / `unittest`）。
- 双缓冲渲染：每帧由场景绘制到 `FrameBuffer`，再整体呈现，避免闪烁。
- 启动入口：`python-demo/main_tui.py` → 主菜单。

### 0.2 核心抽象

| 抽象 | 说明 |
|------|------|
| **动作名（action）** | 按键被抽象为动作字符串（如 `UP`/`CONFIRM`/`open_tech`），而非具体按键。场景按 `event.action` 分支，与物理键解耦，便于改键。 |
| **场景栈（scene stack）** | 界面以栈组织。打开子界面 = `PUSH` 压入新场景；返回 = `POP` 弹出。栈顶场景独占输入与渲染。 |
| **回值通道（on_return）** | 子场景 `POP(value)` 携带一个回值；框架弹出子场景（调用其 `on_exit` 仅做清理，不承担回值），把 `value` 交付给弹回栈顶的场景在 `on_return(value)` 中接收。`on_return` 可返回一个 `SceneResult` 让框架**立即**继续栈转换（如直接 `POP()` 弹出自身回上层，或 `PUSH(...)` 推入消息框）——返回 `NONE()`/`None` 则不再产生栈动作。这让"返回主菜单"等跳转在同一帧内完成，无需待决标志中转。`on_exit` 与 `on_return` 职责分离：前者只清理，后者接收回值并可触发跳转。 |
| **键提示栏（hints_row）** | 每个场景用类属性 `hints_row` 声明键提示栏的绘制位置：`"bottom"`（默认，画在 h-1 行）/ `"top"`（第 0 行）/ 任意 int 行 / `None`（框架不画，场景完全自管 chrome）。框架在场景 `render()` 之后于该行调用 `render_hints(buf, y, w)`；默认实现用 `draw_hints` 横排画 `get_hints()`，子类可重写以分色等自定义格式。 |
| **实时百科** | 任意游戏内场景按 `H` 可进入模糊搜索百科，输入即筛选，无回车阻塞。 |
| **状态总览 overlay** | 游戏内场景按住 `Tab` 显示"帝国总览"浮层；松开即消失。 |

### 0.3 全局操作键

以下按键在**所有场景**中行为一致（主菜单除外，见 §1.3）：

| 按键 | 动作 | 行为 |
|------|------|------|
| 方向键 ↑↓←→ | `UP/DOWN/LEFT/RIGHT` | 移动焦点 / 切换条目 / 在多窗口间逐层进入与回退（具体语义随场景） |
| 空格 | `SELECT` | 选中 / 反选 / 在树场景中切换左↔右焦点 |
| 回车 | `CONFIRM` | 确认 / 执行当前焦点项 / 学习 / 招募等 |
| Backspace | `BACKSPACE` | 输入框回退一个字符（百科搜索框内） |
| PgUp / PgDn | `SCROLL_UP / SCROLL_DOWN` | 滚动详情文本（科技/文化树右侧） |
| ESC | `BACK` | 返回上一级；最顶层时退出当前场景 |
| 按住 Tab | （overlay） | 显示状态总览浮层（游戏内场景） |
| H | `OPEN_WIKI` | 进入百科（游戏内场景） |

> **Alt 不可捕获**：`msvcrt` 无法捕获单独的 Alt 按下，故原规格中"alt 进入详情"的功能由**空格**（`SELECT`）承担，在树场景中切换左侧列表与右侧详情之间的焦点。

### 0.4 游戏专属绑定键

游戏主场景额外绑定以下字母键，直接打开对应子场景（无焦点网格、无需先选中再确认）。这些是动作名（非框架导航动作），在 `pydemo/tui/actions.py` 中定义：

| 按键 | 动作 | 打开场景 |
|------|------|----------|
| K | `open_tech` | 科技树 |
| W | `open_culture` | 文化树 |
| H | `open_wiki` | 百科 |
| J | `open_diplomacy` | 外交 |
| C | `open_stronghold` | 据点一览 |
| A | `open_army` | 部队一栏 |
| Z | `open_recruit` | 招募一览 |
| M | `open_map` | 地图一览（全屏地图，与主场景内嵌地图同渲染） |
| T | `end_turn` | 结束本回合（推进 AI 行动与时间） |
| N | `new_army` | 新建部队（**仅部队场景、且焦点在最左侧窗口时**） |
| 1 / 2 / 3 / 4 | `filter_1..4` | 列表筛选（科技/文化树、部队一栏） |

> 主场景顶部 y=0 行实时列出当前可用的绑定键（键名 ACCENT + 说明 DIM），由框架原生绘制（`hints_row="top"` + 重写 `render_hints`），无需场景自绘。省略 ↑↓/回车 提示——主场景无焦点网格。

### 0.5 焦点与高亮约定

- **焦点行**：当前可选中的条目用反色块（`SELECTED_FG` on `SELECTED_BG`）整行高亮，前置 `▶` 标记。
- **窗口焦点边框**：当前焦点所在窗口的边框用强调色（`ACCENT`），非焦点窗口用普通边框色（`BORDER`）。
- **面包屑**：多窗口嵌套场景在顶部显示层级路径（如 `据点: 隘口 > 槽0: 市场 > 操作: 建造`），标示焦点所处层级。

### 0.6 颜色语义（全局）

| 色 | 语义 |
|----|------|
| 绿（41） | 己方 / 我方据点 / 已学习 |
| 红（196） | 敌方 / 敌方据点 / 未满足前置（不可学习） |
| 白（254） | 中立 / 可学习（前置满足且资源足够） |
| 黄（221） | 可学习但资源不足（前置满足） |
| 金（GOLD） | 资源数值（充足时） |
| 暗灰白（245） | 小地点 |
| 警告色（WARN） | 资源不足 / 操作非法 / 占位提示 |

```
┌─ The Great Conquest ──────────────────────────────┐
│            [ASCII Logo: The Great Conquest]        │
│            4X 回合制策略 · TUI 演示                 │
│                                                    │
│              >  继续游戏                            │
│                 开始游戏                            │

│                                                    │

```

### 1.2 菜单项

| 序 | 项 | 行为 |
|----|----|------|
| 1 | 继续游戏 | 读取存档（占位：当前仅读取标记存档的天数），以 `MessageScene` 提示结果 |

- **仅** `↑` / `↓` / 回车 可用：上下移动焦点（循环），回车确认。

- 焦点行用反色高亮 + `>` 前置标记。

## 2. 游戏主场景（地图作主场景）

游戏主场景以**地图拓扑图**作为主画面，玩家始终面对大地图进行决策。顶部三行依次为"可用按键操作 / 日历 / 资源+信念"，底部最末一行为日志信息栏。原"绑定键面板网格"已取消——绑定键直接生效，无需先移动焦点再确认。

### 2.1 布局

```
┌────────────────────────────────────────────────────────────────────┐
│ K 科技  W 文化  H 百科  J 外交  C 据点  A 部队  Z 招募  M 地图  T 下一回合  ESC 选单  Tab 总览 │  y=0 可用按键操作
│ 第 3 天 · 白天 · 满月(魔力恢复 +6)                                  │  y=1 日历
│ 玩家阵营  金币:50 食物:30 …  道德:+20 功利:+0 自由:+0               │  y=2 资源+信念
├────────────────────────────────────────────────────────────────────┤
│                                                                      │
│              ◆首都 [4](我)─────·隘口─────◆矿场 [2](敌)                │
│                            │                                         │
│                          ◆隘口2                                      │
│                    （地图拓扑：据点/小地点 + 连线 + 驻军数）          │
│                                                                      │
│  ◆我方  ◆敌方  ◆中立  ·小地点  [N]=该据点驻军存活单位数              │
├────────────────────────────────────────────────────────────────────┤
│ 日志 已学习 文字工艺 │ 先锋军 移动至 隘口 │ …                          │  y=h-1 日志
└────────────────────────────────────────────────────────────────────┘
```

| 行 | 内容 |
|----|------|
| y=0 | **当前场景可用按键操作**：由框架经 `hints_row="top"` 在该行原生绘制（场景重写 `render_hints`：键名 ACCENT、说明 DIM 横排）。内容随场景动态变化（主场景列出全部绑定键，子场景返回后恢复） |
| y=1 | **日历**：`第 N 天 · 时段 · 月相(魔力恢复 +X)`（`calendar.describe()`） |
| y=2 | **资源+信念**：阵营名 + 全局资源数值（非零，`RESOURCE_CN` 中文名；金币=GOLD，科技/文化/信仰=ACCENT，其余=FG）+ 信念三维度数值（右侧，ACCENT2） |
| y=3..h-2 | **地图拓扑**：据点 `◆`/小地点 `·` + 名称 + 连线 + 野战部队数 `[N]`，按归属着色 |
| y=h-1 | **日志信息栏**：最近 3 条日志，` │ ` 分隔，普通=DIM，警告/错误=WARN |

> 操作提示行（y=0）由框架经 `hints_row="top"` 原生绘制（场景重写 `render_hints` 以分色显示键名/说明），替代了原"底部键提示栏"。底部最末一行由主场景自绘为日志栏。省略"↑↓ 移动""回车 确认"提示——主场景已无焦点网格可移动，绑定键直接生效。

> 背景：月相 14 天一周期驱动魔力恢复；昼夜每 7 天切换一个时段。两套周期独立运行，状态栏同时展示二者，提示玩家把握交战时机。

### 2.2 操作

| 按键 | 行为 |
|------|------|
| K / W / H / J / C / A / Z / M | 直接打开对应子场景（`PUSH`） |
| T | 结束本回合：执行 AI 行动 → 时间推进 → 重置行动标记 → 判定胜负 → 进入玩家回合。若游戏结束，`PUSH` 胜者消息框，并设待决标志，下次按键返回主菜单 |
| ESC | `PUSH` 退出选单（§2.5） |
| 按住 Tab | 显示帝国总览浮层（§2.4） |

> 主场景**不接受** ↑↓←→ / 回车作为导航（已无焦点网格）。这些键在主场景顶层无效果；方向键与回车的导航语义在各子场景内有效。

### 2.3 地图主画面

- 据点 `◆名称 [野战部队存活单位数](归属)`：己方=绿 / 敌方=红 / 中立=白；首都标 `(都)`。
- 小地点 `·名称 [N]`：仅在该节点有野战部队时显示 `[N]`，否则不显示。
- `[N]` 为该节点**野战部队**（非驻军）存活单位数，颜色：仅我方=绿、仅敌方=红、双方接触=黄。驻军不单独显示——据点归属色已反映驻军阵营，攻城难度由归属与野战接触体现。
- 节点间用 `─│╲╱` + 拐角 `┐└┌┘` 连线，表示固定路径。
- 坐标按剧本固定 `(x,y)` 紧凑缩放（x 拉满宽度，y 自适应刻度）。
- 地图右侧底部为图例。地图为只读视图，操作经绑定键进入各子场景。
- **即时更新**：地图每帧从游戏状态现算各节点野战部队，故创建部队、移动/攻击后返回主场景即看到变化（玩家移动是即时的，无需等回合结束）。

> 地图把战略重心从"如何移动"转到"何时、向哪里用兵"：节点与固定连线决定可达性，`[N]` 野战部队数提示该节点当前接触强度。地图既可作主场景背景，也可经 `M` 打开为独立全屏地图场景（同一拓扑渲染）。

### 2.4 帝国总览 overlay（按住 Tab）

按住 Tab 时居中浮出 60×16 的总览面板（`render_overlay` 返回 `True`，跳过框架默认 overlay）：

- 阵营名、日历描述、据点/部队/英雄数量。
- 信念三维度数值。
- 全部 11 种资源数值（两列布局）。
- 若游戏已结束，底部显示胜者。

松开 Tab 即消失。所有游戏内场景均支持此 overlay（`allow_status_overlay=True`）。

### 2.5 退出选单（ESC 菜单）

ESC 弹出居中模态选单，**半透明遮罩**覆盖主场景：

| 项 | 行为 |
|----|------|
| 继续游戏 | `POP`（关闭选单） |
| 保存 | 写入标记存档（占位：仅记录天数）+ `PUSH` 消息框 |
| 读取 | 读取标记存档（占位）+ `PUSH` 消息框 |
| 返回主菜单 | `POP("to_menu")` —— 主场景 `on_return` 收到后**直接返回 `POP()`**，框架同帧弹出主场景回到主菜单（无需再按键中转） |

- `↑↓` 切换，回车/空格确认，ESC 关闭选单（等同"继续游戏"）。
- **结束回合不在选单内**，由专用 `T` 键触发。

> 存档/读档为占位实现：完整 `Game.snapshot()/restore()` 序列化留待业务层扩展。返回值经 `on_return` 通道传递；`on_return` 可返回 `SceneResult` 直接触发跳转，故"返回主菜单"同帧完成。

## 3. 科技树 / 文化树界面

科技树与文化树**同构**，共享一套交互。差异仅在数据来源与已学集合。

### 3.1 布局

```
┌─ 科技树 ──────────────────────────────────────────┐
│ 1 全部   2 已学习   3 未学习   4 可学习             │  ← 筛选行
├───────────────────┬────────────────────────────────┤
│ 项目名称列表（左） │ 详细说明（右）                  │
│  ▶ 文字工艺        │  名称 / 分类 / 说明             │
│    铸币术          │  解锁项 / 花费 / 跳转词条       │
│    ...             │                                │
└───────────────────┴────────────────────────────────┘
```

左右等宽分割，中间以 `│` 分隔。左侧为项目名称列表，右侧为选中项目的详情。

### 3.2 筛选（数字键 1234）

| 键 | 筛选 | 含义 |
|----|------|------|
| 1 | 全部 | 所有项目 |
| 2 | 已学习 | 仅已学习项目 |
| 3 | 未学习 | 仅未学习项目 |
| 4 | 可学习 | 前置条件已满足且尚未学习（含白色与黄色状态） |

切换筛选时焦点与滚动复位。当前筛选项用 ACCENT 高亮。

### 3.3 颜色状态（左侧列表）

每个项目按状态着色：

| 色 | 状态 | 条件 |
|----|------|------|
| 绿 | 已学习 | 已在已学集合中 |
| 白 | 可学习 | 前置全部满足 **且** 资源足够 |
| 红 | 锁定 | 前置未满足 |
| 黄 | 资源不足 | 前置满足但资源不足 |

### 3.4 左侧（列表焦点）操作

| 按键 | 行为 |
|------|------|
| ↑↓ | 在筛选后列表中移动焦点（循环） |
| 回车 | 学习焦点项目：校验前置（`prereqs ⊆ learned`）与资源（`can_afford`）；通过则扣资源 + 加入已学集合 + 日志"学习了 X"；否则日志警告原因 |
| 空格 | 切换焦点到右侧详情 |
| PgUp/PgDn | 滚动列表 |
| ESC | 退出本场景（`POP`） |

### 3.5 右侧（详情焦点）操作

详情区显示：项目名称、分类、文字说明、解锁项、学习花费、跳转词条。文字说明中以 `[[词]]` 标记的词条为**跳转词条**，渲染时去方括号以强调色显示。

| 按键 | 行为 |
|------|------|
| ↑↓ | 在跳转词条间切换焦点 |
| 回车 | 打开百科并自动导航到当前词条（`PUSH WikiScene({"query": 词})`） |
| PgUp/PgDn | 滚动详情文本 |
| 空格 | 焦点切回左侧 |
| ESC | 焦点切回左侧（不退出场景）；在左侧时再按 ESC 才退出 |

### 3.6 学习与业务层关系

> 业务层当前**无**科技/文化系统。学习记录保存在 TUI 控制器（`ctrl.tech_learned` / `ctrl.culture_learned`），资源在 TUI 侧从玩家阵营扣除，**不影响战斗与经济**。这是计划内的占位，待业务层接入后再打通效果。

## 5. 据点界面

四层嵌套窗口，用方向键右逐层进入、方向键左回退。这是本游戏操作复杂度最高的场景。

### 5.1 布局（4 窗口）

```
┌─ 据点一览 ──────────────────────────────────────────┐
│ 据点: 隘口 > 槽0: 市场 > 操作: 建造 > 候选: 农场       │  ← 面包屑
├───────────┬──────────┬──────────┬────────────────────┤
│ W1 据点    │ W2 据点  │ W3 槽位  │ W4 候选            │
│ ◆首都(都) │ 详情     │ 操作     │ 建造/指派目标      │
│ ◆隘口     │ 槽位+部队│ 建造拆除 │                    │
│ ◆矿场     │          │ 指派     │                    │
└───────────┴──────────┴──────────┴────────────────────┘

```

四个窗口左右排列，焦点逐层进入：

| 层 | 窗口 | 内容 |
|----|------|------|
| L0 | W1 大地图据点 | 所有据点名称，按归属着色（己方=绿 / 敌方=红 / 中立=白），首都标 `(都)` |
| L1 | W2 单据点详情 | 选中据点的槽位（建筑名或"空槽"，建造中标 `(建造中)`）+ 驻于该据点的部队（驻军标 `(驻军)`） |
| L2 | W3 槽位操作 | 空槽：`建造` `指派`；有建筑：`拆除` `指派` |
| L3 | W4 候选 | 建造候选建筑（含花费、是否负担得起）/ 指派候选英雄 |

### 5.2 通用操作

| 按键 | 行为 |
|------|------|
| ↑↓ | 当前层内切换条目 |
| → | 进入下一层（若允许） |
| ← | 回退上一层 |
| 回车 | 等同 `→`（进入下层），或在 W3/W4 执行操作 |
| ESC | 回退一层；在 W1 时退出场景 |

### 5.3 各层进入规则

- **L0 → L1**：在任意据点按 `→`/回车，进入 W2。
- **L1 → L2（槽位）**：焦点在槽位上按 `→`/回车，进入 W3 操作。**非己方据点不可**，日志警告"非己方据点，不可操作"。
- **L1 → 部队操作**：焦点在部队上按 `→`/回车：若是己方非驻军部队，`PUSH ArmyScene({"army_id":...})` 委托部队场景操作（等同于部队一览）；驻军不可编辑。
- **L2 → L3**：建造/指派按 `→`/回车进入 W4 选目标；**拆除直接回车确认**执行（删除该槽位建筑），不进 W4。
- **L3 确认**：回车执行 —— 建造走 `action_build`（资源/槽位校验），指派写入 `player.lords[sh.id]=hero`；执行后回退到 L1。

> 非己方据点可查看 W2，但**不能继续向右操作**（槽位与部队均拒绝）。这把"查看敌方布防"与"操作己方建设"清晰分开。

### 5.4 业务层缺口

> 业务层无据点"拆除/指派领主"接口：拆除用直接 `buildings` 列表删除，指派用直接 `player.lords[sh.id]` 写入。建造走 `Game.action_build`（有资源/槽位校验）。这是计划内的占位。

## 6. 部队界面

三窗口 + 单位详情模式。窗口布局会随焦点在单位上的状态**重排**。

### 6.1 布局（3 窗口）

```
┌─ 部队一栏 ─────────────────────────────────────────┐
│ 1 我方   2 敌方   3 驻军   4 全部                    │  ← 筛选行
├──────────────┬──────────────┬───────────────────────┤
│ W1 部队列表  │ W2 部队操作 │ W3 阵型（九宫格）      │
│  ▶ 先锋军    │  移动        │ 规模 6/9  补给 10/10   │
│    守备军    │  编辑        │ 位置 隘口              │
│              │  解散        │ 1列 2列 3列            │
│              │              │ 前排 … … …            │
└──────────────┴──────────────┴───────────────────────┘
1我方 2敌方 3驻军 4全部  N新建(仅W1)  →进入 ←回退  回车确认
```

| 窗口 | 常态（army 模式） | 单位模式（焦点在 W3 单位上） |
|------|-------------------|------------------------------|
| W1 | 部队名称列表 | **单位详情**（名称/词条/英雄/属性/生命） |
| W2 | **部队操作**：移动 / 编辑 / 解散 | **单位操作**：换位 / 上场 / 下场 / 编辑装备 |
| W3 | 部队规模 + 补给 + 位置 + 九宫格 | 同左（保持阵型显示） |

### 6.2 筛选（数字键 1234）

| 键 | 筛选 | 含义 |
|----|------|------|
| 1 | 我方 | 玩家非驻军部队（数字 1 永远是真人玩家） |
| 2 | 敌方 | 其他阵营非驻军部队 |
| 3 | 驻军 | 据点驻军 |
| 4 | 全部 | 全部部队 |

切换筛选时焦点复位。

### 6.3 焦点层级与操作

焦点分三层：W1（level 0）→ W2（level 1）→ W3（level 2）。方向键右逐层进入，左回退。

| 按键 | 行为 |
|------|------|
| ↑↓ | 当前层内切换条目；在 W3 单位间移动会**自动进入单位模式** |
| → | W1→W2→W3 逐层进入 |
| ← | 回退一层；若在移动/换位模式，则取消该模式 |
| 回车 | 进入下一层 / 执行 W2 操作 / 在 W3 选中单位进单位模式 |
| N | **仅 W1 时**新建部队（§6.5） |
| ESC | 取消移动/换位模式 → 退出单位模式 → 回退一层 → 退出场景 |

### 6.4 部队操作（W2，army 模式）

仅**本方部队**可操作；非本方部队 W2 仅可查看，日志警告"非本方部队，不可操作"。

| 操作 | 行为 |
|------|------|
| 移动 | 进入移动模式：W3 列出距当前位置距离 1 的邻接地点（见 §6.6）。若该地有敌方非驻军部队或敌方据点，标 `[攻击]`。回车确认 → `action_move_attack`（移动或攻城）。本回合已行动则警告 |
| 编辑 | 占位：业务层暂未开放，日志警告 |
| 解散 | `disband_army`（直接丢弃单位，**不入聚贤庄**——见 §8 缺口） |

### 6.5 新建部队（N，仅 W1）

- 仅当焦点在最左侧窗口（W1）时可用。
- 在当前选中部队所在据点（或玩家首都）寻找一名**无部队的英雄**，`create_army` + `set_captain` 建队；若无可用英雄，日志警告。
- 建队后自动切到"我方"筛选并聚焦到新部队。

> 背景：部队必须由英雄任队长，队长的意志决定部队最大规模。无英雄则无法建队。

### 6.6 移动与攻击

- 移动以"跳"（Hop）为原子单位，每回合默认 1 跳（跨一个邻接结点）。
- 目的地为距离 1 的邻接结点。若该处有敌方**非驻军**部队，或该处为**敌方据点**，标记 `[攻击]`，本次移动即发起战斗。
- 每支部队每回合**主动发起的战斗最多 1 场**；被动防守不限次。
- 战斗自动结算（200 Tick）；未分胜负则防守方留守、进攻方退回出发结点。

### 6.7 单位操作（W2，单位模式）

焦点在 W3 单位上时进入单位模式，W1 变为单位详情，W2 变为单位操作。

| 操作 | 行为 |
|------|------|
| 换位 | 进入换位模式：W3 列出空位，回车将当前单位与空位交换（直接 `grid` 槽位交换） |
| 上场 | 占位：业务层暂无离场概念，日志警告 |
| 下场 | 占位：同上 |
| 编辑装备 | 占位：业务层暂未开放，日志警告 |

> 单位为 3×3 九宫格，分前/中/后三排；近战只能攻同列或邻列前排，远程/魔法可越排，前排掩护同列后排。换位用于调整站位策略。

### 6.8 经据点界面委托进入

据点场景可经 `PUSH ArmyScene({"army_id":...})` 直接聚焦到指定部队，等同于部队一览操作，提供按据点查看部队的入口。

### 6.9 业务层缺口

> 上场/下场/编辑装备：业务层无离场概念、无装备系统 → 占位警告。换位通过直接 `grid` 交换实现（安全）。解散当前直接丢弃单位而非进入聚贤庄。

## 7. 招募界面

三窗口对应当前据点招募池的 3 名英雄，回车招募，成功后留在本场景（被招募的窗口置空，其余英雄原位保留）。

### 7.1 布局（3 窗口）

```
┌─ 招募一览 ─────────────────────────────────────────┐
│ 据点: 首都  (池中 3/3 · 下次刷新 第14天)  [1/2] ↑↓切换 │
├──────────────┬──────────────┬───────────────────────┤
│ W1 英雄 1    │ W2 英雄 2    │ W3 英雄 3              │
│ 名称         │ 名称         │ 名称                   │
│ 词条         │ 词条         │ 词条                   │
│ 招募费用     │ 招募费用     │ 招募费用               │
│ 信念要求     │ 信念要求     │ 信念要求               │
│ 基础属性     │ 基础属性     │ 基础属性               │
│ 技能         │ 技能         │ 技能                   │
└──────────────┴──────────────┴───────────────────────┘
↑↓ 切换据点  ←→ 选择英雄  回车 招募  ESC 返回
```

每个窗口显示一名英雄：名称（HEADING）、词条（DIM）、招募费用（充足=GOLD，不足=WARN）、信念要求、基础属性（11 项）、技能（ACCENT2）。空窗口显示"（空位）已被招募"（该槽已招募）或"（空位）等待下次刷新"（无池/刷新未出）。3 个都招满即 3 个空栏位。

### 7.2 操作

| 按键 | 行为 |
|------|------|
| ↑↓ | 切换己方据点（每个据点独立招募池，每 14 天刷新 3 个）。多据点时头部显示 `[i/N] ↑↓切换` |
| ←→ | 在 3 个窗口（英雄）间移动焦点 |
| 回车 | 招募焦点窗口的英雄：走 `action_recruit_hero`（资源/信念校验）；成功则日志 + **留在本场景**（被招募窗口置空，其余英雄原位保留）；失败则日志警告并留在本场景 |
| ESC | 返回枢纽 |

### 7.3 招募后的流程

> 招募成功后**留在本场景**：被招募的窗口置空显示"（空位）已被招募"，其余英雄原位保留，可继续招募直到该据点池满。业务层 `action_recruit_hero` 招募英雄后将其送入**聚贤庄**（`hall_of_worthies`）待命，**不自动创建部队**——招募只产生英雄单位，不强制其上战场。英雄暂留于招募据点（`u.node_id=stronghold_id`），玩家可后续在据点界面（§5）将其**指派为该据点领主**（`player.lords[sh.id]=hero_id`），或在部队界面（§6.5）新建部队时任队长——两种路径均按"该据点的无部队英雄"检索，故被招募的英雄自动成为候选。聚贤庄场景（§8）暂未在主流程挂接入口（待业务层扩展召唤/登场/冷却机制后绑定按键或流程后入口）。

> 背景：英雄招募消耗资源并需满足信念门槛；每据点独立刷新，每 14 天（一个月相周期）刷 3 个。招募池刷新由业务层 `tick_economy` 每 14 天自动执行，TUI 只读 `pool.offerings`。`offerings` 为**固定 3 槽**列表（hero_def id 或 `None` 空位）：招募把对应槽位置 `None`，**不压缩**其余英雄——故三窗口与槽位一一对应，被招募的窗口才空，其余英雄原位保留，直到下次刷新重填 3 槽。每刷新周期、每据点可分次招满 3 名。

## 8. 聚贤庄界面（只读 · 暂未挂接入口）

聚贤庄（英雄厅）用于容纳招募后、尚未指派或编入部队的英雄在此待命。业务层 `Faction.hall_of_worthies`（英雄单位 id → 冷却回合）现由 `action_recruit_hero` 填充：招募不再自动创建部队，英雄直接进入聚贤庄并暂留于招募据点（`u.node_id=stronghold_id`），等待玩家后续操作——

- **指派为据点领主**（据点界面 §5.3 L3「指派」）：候选条件为「该据点的无部队英雄」，被招募的英雄自动满足，可直接指派。
- **新建部队任队长**（部队界面 §6.5「N 新建」）：同样按「该据点的无部队英雄」检索，被招募的英雄自动成为候选。

由于「指派/建队」入口已在据点/部队界面就绪，且玩家可在招募后立即操作，聚贤庄场景**暂不单独挂接入口**：避免多一个跳转层级。当前业务层尚无「召唤登场/冷却推进/遣散入厅」机制，聚贤庄内英雄即「已就位、可指派」状态，无独立操作面。待业务层扩展召唤/登场/冷却机制后，再在主场景绑定一个键（如新增）或招募流程后挂接聚贤庄入口，届时 `pydemo/tui/scenes/hall.py` 直接复用。

### 8.1 业务层缺口

> `Faction.hall_of_worthies`（英雄→冷却）现由 `action_recruit_hero` 填充（招募入厅），但**召唤登场 / 冷却推进 / 遣散入厅**尚无业务层接口：英雄一旦招募即处于「可指派」状态（冷却恒为 0），无冷却门槛、无主动召唤动作。遣散部队当前直接丢弃单位而非进入聚贤庄。召唤/登场/冷却推进需业务层扩展后，再恢复聚贤庄场景挂接（`pydemo/tui/scenes/hall.py` 已就绪，仅未在主流程中 `PUSH`）。

## 11. 制作约束：框架与业务分离

- **框架**（`pyconsole`）可复用、可由本仓库独立演进（源自 `U:\pyFramework` 的副本，现已允许按需扩展，但游戏特定逻辑不得渗入框架——扩展限于通用能力，如键提示栏位置 `hints_row` 与回值通道 `on_return` 这类框架级特性）。
- **业务层**（`pydemo/game/`）为纯逻辑、无 IO，不依赖任何界面。
- **交互层**（`pydemo/tui/`）位于二者之间：用框架的渲染与输入抽象，调用业务层的逻辑函数，把结果以日志/状态反馈给玩家。
- 动作常量分两处：框架导航动作在 `pyconsole.core.actions`，游戏专属动作在 `pydemo.tui.actions`，**不可混用**。
- 可替换性：语言、美术资源、按键绑定在设计上预留接口（动作名抽象、主题色集中、数据 JSON 化）。
- mod 支持：`mods/` 文件夹下同名 JSON 整条覆盖基础定义，实现数值的追加与修改，但主流程硬编码不可改。
