# 操作逻辑说明

本文档是 TheGreatConquest（TUI 演示版）的**操作交互规格**。它定义了玩家在终端界面中可执行的所有交互选项、各场景的有限状态机，以及视觉状态（焦点、颜色、筛选）的语义。它是 UI 实现的契约：框架（`pyconsole`）负责渲染与输入抽象，业务层（`pydemo/game/`）负责游戏逻辑，本文档描述两者之间的交互层。

> 本文只描述"怎么操作"，不描述游戏机制本身。游戏总设计见 [README.md](README.md)，术语定义见 [CONTEXT.md](CONTEXT.md)。本文档内的机制说明仅作为操作的背景，用以说明某个交互为何如此设计。

---

## 0. 框架与全局约定

### 0.1 运行环境

- 终端固定为 **100 列 × 30 行**（`SCREEN_W=100, SCREEN_H=30`）。
- 零第三方依赖，仅使用 Python 标准库（`msvcrt` / `ctypes` / `json` / `unicodedata` / `unittest`）。
- 双缓冲渲染：每帧由场景绘制到 `FrameBuffer`，再整体呈现，避免闪烁。
- 启动入口：`python-demo/main_tui.py` → 主菜单。

### 0.2 核心抽象

| 抽象 | 说明 |
|------|------|
| **动作名（action）** | 按键被抽象为动作字符串（如 `UP`/`CONFIRM`/`open_tech`），而非具体按键。场景按 `event.action` 分支，与物理键解耦，便于改键。 |
| **场景栈（scene stack）** | 界面以栈组织。打开子界面 = `PUSH` 压入新场景；返回 = `POP` 弹出。栈顶场景独占输入与渲染。 |
| **回值通道（on_return）** | 子场景 `POP(value)` 携带一个回值；框架弹出子场景（调用其 `on_exit` 仅做清理，不承担回值），把 `value` 交付给弹回栈顶的场景在 `on_return(value)` 中接收。`on_return` 可返回一个 `SceneResult` 让框架**立即**继续栈转换（如直接 `POP()` 弹出自身回上层，或 `PUSH(...)` 推入消息框）——返回 `NONE()`/`None` 则不再产生栈动作。这让"返回主菜单"等跳转在同一帧内完成，无需待决标志中转。`on_exit` 与 `on_return` 职责分离：前者只清理，后者接收回值并可触发跳转。 |
| **键提示栏（hints_row）** | 每个场景用类属性 `hints_row` 声明键提示栏的绘制位置：`"bottom"`（默认，画在 h-1 行）/ `"top"`（第 0 行）/ 任意 int 行 / `None`（框架不画，场景完全自管 chrome）。框架在场景 `render()` 之后于该行调用 `render_hints(buf, y, w)`；默认实现用 `draw_hints` 横排画 `get_hints()`，子类可重写以分色等自定义格式。 |
| **实时百科** | 任意游戏内场景按 `H` 可进入模糊搜索百科，输入即筛选，无回车阻塞。 |
| **状态总览 overlay** | 游戏内场景按住 `Tab` 显示"帝国总览"浮层；松开即消失。 |
| **全局日志栏** | 所有游戏内子场景在最末第二行（y=h-2）绘制统一日志栏（最近 3-4 条，` │ ` 分隔，普通=DIM、警告=WARN），复用 `pydemo/tui/log.py` 的 ring buffer。键提示由框架在 h-1 行绘制。主场景则把日志放在最末行（y=h-1）。 |

### 0.3 全局操作键

以下按键在**所有场景**中行为一致（主菜单除外，见 §1.3）：

| 按键 | 动作 | 行为 |
|------|------|------|
| 方向键 ↑↓←→ | `UP/DOWN/LEFT/RIGHT` | 移动焦点 / 切换条目 / 在多窗口间逐层进入与回退（具体语义随场景） |
| 空格 | `SELECT` | 选中 / 反选 / 在树场景中切换左↔右焦点 |
| 回车 | `CONFIRM` | 确认 / 执行当前焦点项 / 学习 / 招募等 |
| Backspace | `BACKSPACE` | 输入框回退一个字符（百科搜索框内） |
| PgUp / PgDn | `SCROLL_UP / SCROLL_DOWN` | 滚动详情文本（科技/文化树右侧） |
| ESC | `BACK` | 返回上一级；最顶层时退出当前场景 |
| 按住 Tab | （overlay） | 显示状态总览浮层（游戏内场景） |
| H | `OPEN_WIKI` | 进入百科（游戏内场景） |

> **Alt 不可捕获**：`msvcrt` 无法捕获单独的 Alt 按下，故原规格中"alt 进入详情"的功能由**空格**（`SELECT`）承担，在树场景中切换左侧列表与右侧详情之间的焦点。

游戏主场景额外绑定以下字母键，直接打开对应子场景（无焦点网格、无需先选中再确认）。这些是动作名（非框架导航动作），在 `pydemo/tui/actions.py` 中定义：

| 按键 | 动作 | 打开场景 |
|------|------|----------|
| K | `open_tech` | 科技树 |
| W | `open_culture` | 文化树 |
| H | `open_wiki` | 百科 |
| J | `open_diplomacy` | 外交 |
| C | `open_stronghold` | 据点一览 |
| A | `open_army` | 部队一栏 |
| Z | `open_recruit` | 招募一览 |
| X | `open_unit` | 单位一览（§8） |
| V | `open_stronghold_overview` | 据点总览（§6） |
| M | `open_map` | 地图一览（全屏地图，与主场景内嵌地图同渲染） |
| T | `end_turn` | 结束本回合（推进 AI 行动与时间） |
| N | `new_army` | 新建部队（**仅部队场景、且焦点在最左侧窗口时**） |
| 1 / 2 / 3 / 4 | `filter_1..4` | 列表筛选（科技/文化树、部队一栏、据点总览、单位一览） |

### 0.5 焦点与高亮约定

- **焦点行**：当前可选中的条目用反色块（`SELECTED_FG` on `SELECTED_BG`）整行高亮，前置 `▶` 标记。
- **窗口焦点边框**：当前焦点所在窗口的边框用强调色（`ACCENT`），非焦点窗口用普通边框色（`BORDER`）。
- **面包屑**：多窗口嵌套场景在顶部显示层级路径（如 `据点: 隘口 > 槽0: 市场 > 操作: 建造`），标示焦点所处层级。

### 0.6 颜色语义（全局）

| 色 | 语义 |
|----|------|
| 绿（41） | 己方 / 我方据点 / 已学习 / 资源净变动为正 |
| 红（196） | 敌方 / 敌方据点 / 未满足前置（不可学习）/ 资源净变动为零或负 |
| 白（254） | 中立 / 可学习（前置满足且资源足够） |
| 黄（221） | 可学习但资源不足（前置满足） |
| 金（GOLD） | 资源数值（充足时） |
| 暗灰白（245） | 小地点 |
| 警告色（WARN） | 资源不足 / 操作非法 / 占位提示 |

## 1. 主菜单

### 1.1 布局

```
┌─ The Great Conquest ──────────────────────────────┐
│            [ASCII Logo: The Great Conquest]        │
│            4X 回合制策略 · TUI 演示                 │
│                                                    │
│              >  继续游戏                            │
│                 开始游戏                            │
│                 退出游戏                            │
│                                                    │
│         ↑↓ 移动 · 回车 选择 · 仅本菜单可用           │
└────────────────────────────────────────────────────┘
```

### 1.2 菜单项

| 序 | 项 | 行为 |
|----|----|------|
| 1 | 继续游戏 | 读取存档（占位：当前仅读取标记存档的天数），以 `MessageScene` 提示结果 |
| 2 | 开始游戏 | 调用 `new_game()` 构建剧本，`PUSH` 游戏主场景（枢纽） |
| 3 | 退出游戏 | `QUIT()` 退出程序 |

### 1.3 操作约束

- **仅** `↑` / `↓` / 回车 可用：上下移动焦点（循环），回车确认。
- **ESC 与 Tab 在主菜单无效**：`BACK` 与 `SELECT` 均被吞掉（规格要求主界面只允许上下与回车）。
- 焦点行用反色高亮 + `>` 前置标记。

## 2. 游戏主场景（地图作主场景）

游戏主场景以**地图拓扑图**作为主画面，玩家始终面对大地图进行决策。顶部三行依次为"可用按键操作 / 日历 / 资源+信念"，底部最末一行为日志信息栏。原"绑定键面板网格"已取消——绑定键直接生效，无需先移动焦点再确认。

### 2.1 布局

```
┌────────────────────────────────────────────────────────────────────┐
│ K 科技 W 文化 H 百科 J 外交 C 据点 A 部队 Z 招募 X 单位 V 据点总览 M 地图 T 下一回合 ESC 选单 Tab 总览 │  y=0 可用按键操作
│ 第 3 天 · 白天 · 满月(魔力恢复 +6)                                  │  y=1 日历
│ 玩家阵营  金币:20(+1) 食物:30(+5) …  道德:+20 功利:+0 自由:+0        │  y=2 资源+信念
├────────────────────────────────────────────────────────────────────┤
│                                                                      │
│              ◆首都 [4](我)─────·隘口─────◆矿场 [2](敌)                │
│                            │                                         │
│                          ◆隘口2                                      │
│                    （地图拓扑：据点/小地点 + 连线 + 驻军数）          │
│                                                                      │
│  ◆我方  ◆敌方  ◆中立  ·小地点  [N]=该据点驻军存活单位数              │
├────────────────────────────────────────────────────────────────────┤
│ 日志 已学习 文字工艺 │ 先锋军 移动至 隘口 │ …                          │  y=h-1 日志
└────────────────────────────────────────────────────────────────────┘
```

| 行 | 内容 |
|----|------|
| y=0 | **当前场景可用按键操作**：由框架经 `hints_row="top"` 在该行原生绘制（场景重写 `render_hints`：键名 ACCENT、说明 DIM 横排）。内容随场景动态变化（主场景列出全部绑定键，子场景返回后恢复） |
| y=1 | **日历**：`第 N 天 · 时段 · 月相(魔力恢复 +X)`（`calendar.describe()`） |
| y=2 | **资源+信念**：阵营名 + 全局资源数值（非零，`RESOURCE_CN` 中文名）。每个资源以"现存(净变动)"形式显示（如 `金币:20(+1)`）——括号前为现存总量、括号内为本回合已结算的净变动；增量 >0 绿、≤0 红。其后接信念三维度数值（右侧，ACCENT2） |
| y=3..h-2 | **地图拓扑**：据点 `◆`/小地点 `·` + 名称 + 连线 + 野战部队数 `[N]`，按归属着色 |
| y=h-1 | **日志信息栏**：最近 3 条日志，` │ ` 分隔，普通=DIM，警告/错误=WARN |

> 操作提示行（y=0）由框架经 `hints_row="top"` 原生绘制（场景重写 `render_hints` 以分色显示键名/说明），替代了原"底部键提示栏"。底部最末一行由主场景自绘为日志栏。省略"↑↓ 移动""回车 确认"提示——主场景已无焦点网格可移动，绑定键直接生效。

> 背景：月相 14 天一周期驱动魔力恢复；昼夜每 7 天切换一个时段。两套周期独立运行，状态栏同时展示二者，提示玩家把握交战时机。

### 2.2 操作

| 按键 | 行为 |
|------|------|
| K / W / H / J / C / V / A / X / Z / M | 直接打开对应子场景（`PUSH`） |
| T | 结束本回合：执行 AI 行动 → 时间推进 → 重置行动标记 → 判定胜负 → 进入玩家回合。若游戏结束，`PUSH` 胜者消息框，并设待决标志，下次按键返回主菜单 |
| ESC | `PUSH` 退出选单（§2.5） |
| 按住 Tab | 显示帝国总览浮层（§2.4） |

> 主场景**不接受** ↑↓←→ / 回车作为导航（已无焦点网格）。这些键在主场景顶层无效果；方向键与回车的导航语义在各子场景内有效。

### 2.3 地图主画面

- 据点 `◆名称 [野战部队存活单位数](归属)`：己方=绿 / 敌方=红 / 中立=白；首都标 `(都)`。
- 小地点 `·名称 [N]`：仅在该节点有野战部队时显示 `[N]`，否则不显示。
- `[N]` 为该节点**野战部队**（非驻军）存活单位数，颜色：仅我方=绿、仅敌方=红、双方接触=黄。驻军不单独显示——据点归属色已反映驻军阵营，攻城难度由归属与野战接触体现。
- 节点间用 `─│╲╱` + 拐角 `┐└┌┘` 连线，表示固定路径。
- 坐标按剧本固定 `(x,y)` 紧凑缩放（x 拉满宽度，y 自适应刻度）。
- 地图右侧底部为图例。地图为只读视图，操作经绑定键进入各子场景。
- **即时更新**：地图每帧从游戏状态现算各节点野战部队，故创建部队、移动/攻击后返回主场景即看到变化（玩家移动是即时的，无需等回合结束）。

> 地图把战略重心从"如何移动"转到"何时、向哪里用兵"：节点与固定连线决定可达性，`[N]` 野战部队数提示该节点当前接触强度。地图既可作主场景背景，也可经 `M` 打开为独立全屏地图场景（同一拓扑渲染）。

### 2.4 帝国总览 overlay（按住 Tab）

按住 Tab 时居中浮出 60×16 的总览面板（`render_overlay` 返回 `True`，跳过框架默认 overlay）：

- 阵营名、日历描述、据点/部队/英雄数量。
- 信念三维度数值。
- 全部 11 种资源数值（两列布局）。
- 若游戏已结束，底部显示胜者。

松开 Tab 即消失。所有游戏内场景均支持此 overlay（`allow_status_overlay=True`）。

### 2.5 退出选单（ESC 菜单）

ESC 弹出居中模态选单，**半透明遮罩**覆盖主场景：

| 项 | 行为 |
|----|------|
| 继续游戏 | `POP`（关闭选单） |
| 保存 | 写入标记存档（占位：仅记录天数）+ `PUSH` 消息框 |
| 读取 | 读取标记存档（占位）+ `PUSH` 消息框 |
| 返回主菜单 | `POP("to_menu")` —— 主场景 `on_return` 收到后**直接返回 `POP()`**，框架同帧弹出主场景回到主菜单（无需再按键中转） |

- `↑↓` 切换，回车/空格确认，ESC 关闭选单（等同"继续游戏"）。
- **结束回合不在选单内**，由专用 `T` 键触发。

> 存档/读档为占位实现：完整 `Game.snapshot()/restore()` 序列化留待业务层扩展。返回值经 `on_return` 通道传递；`on_return` 可返回 `SceneResult` 直接触发跳转，故"返回主菜单"同帧完成。

## 3. 科技树 / 文化树界面

科技树与文化树**同构**，共享一套交互。差异仅在数据来源与已学集合。

### 3.1 布局

```
┌─ 科技树 ──────────────────────────────────────────┐
│ 1 全部   2 已学习   3 未学习   4 可学习             │  ← 筛选行
├───────────────────┬────────────────────────────────┤
│ 项目名称列表（左） │ 详细说明（右）                  │
│  ▶ 文字工艺        │  名称 / 分类 / 说明             │
│    铸币术          │  解锁项 / 花费 / 跳转词条       │
│    ...             │                                │
└───────────────────┴────────────────────────────────┘
```

左右等宽分割，中间以 `│` 分隔。左侧为项目名称列表，右侧为选中项目的详情。

### 3.2 筛选（数字键 1234）

| 键 | 筛选 | 含义 |
|----|------|------|
| 1 | 全部 | 所有项目 |
| 2 | 已学习 | 仅已学习项目 |
| 3 | 未学习 | 仅未学习项目 |
| 4 | 可学习 | 前置条件已满足且尚未学习（含白色与黄色状态） |

切换筛选时焦点与滚动复位。当前筛选项用 ACCENT 高亮。

### 3.3 颜色状态（左侧列表）

每个项目按状态着色：

| 色 | 状态 | 条件 |
|----|------|------|
| 绿 | 已学习 | 已在已学集合中 |
| 白 | 可学习 | 前置全部满足 **且** 资源足够 |
| 红 | 锁定 | 前置未满足 |
| 黄 | 资源不足 | 前置满足但资源不足 |

### 3.4 左侧（列表焦点）操作

| 按键 | 行为 |
|------|------|
| ↑↓ | 在筛选后列表中移动焦点（循环） |
| 回车 | 学习焦点项目：校验前置（`prereqs ⊆ learned`）与资源（`can_afford`）；通过则扣资源 + 加入已学集合 + 日志"学习了 X"；否则日志警告原因 |
| 空格 | 切换焦点到右侧详情 |
| PgUp/PgDn | 滚动列表 |
| ESC | 退出本场景（`POP`） |

### 3.5 右侧（详情焦点）操作

详情区显示：项目名称、分类、文字说明、解锁项、学习花费、跳转词条。文字说明中以 `[[词]]` 标记的词条为**跳转词条**，渲染时去方括号以强调色显示。

| 按键 | 行为 |
|------|------|
| ↑↓ | 在跳转词条间切换焦点 |
| 回车 | 打开百科并自动导航到当前词条（`PUSH WikiScene({"query": 词})`） |
| PgUp/PgDn | 滚动详情文本 |
| 空格 | 焦点切回左侧 |
| ESC | 焦点切回左侧（不退出场景）；在左侧时再按 ESC 才退出 |

### 3.6 学习与业务层关系

> 业务层当前**无**科技/文化系统。学习记录保存在 TUI 控制器（`ctrl.tech_learned` / `ctrl.culture_learned`），资源在 TUI 侧从玩家阵营扣除，**不影响战斗与经济**。这是计划内的占位，待业务层接入后再打通效果。

## 4. 外交界面

占位场景。

### 4.1 布局与操作

- 仅 `ESC` 退出（`POP`）。
- `allow_status_overlay=True`（支持 Tab 总览）。

## 5. 据点界面

四层嵌套窗口，用方向键右逐层进入、方向键左回退。这是本游戏操作复杂度最高的场景。

### 5.1 布局（4 窗口）

```
┌─ 据点一览 ──────────────────────────────────────────┐
│ 据点: 隘口 > 槽0: 市场 > 操作: 建造 > 候选: 农场       │  ← 面包屑
├───────────┬──────────┬──────────┬────────────────────┤
│ W1 据点    │ W2 据点  │ W3 槽位  │ W4 候选            │
│ ◆首都(都) │ 详情     │ 操作     │ 建造/指派目标      │
│ ◆隘口     │ 槽位+部队│ 建造拆除 │                    │
│ ◆矿场     │          │ 指派     │                    │
└───────────┴──────────┴──────────┴────────────────────┘
图例: ◆首都  绿=我方  红=敌方  白=中立  ·  →进入 ←回退 回车确认
```

四个窗口左右排列，焦点逐层进入：

| 层 | 窗口 | 内容 |
|----|------|------|
| L0 | W1 大地图据点 | 所有据点名称，按归属着色（己方=绿 / 敌方=红 / 中立=白），首都标 `(都)` |
| L1 | W2 单据点详情 | 选中据点的槽位（建筑名或"空槽"）+ 驻于该据点的部队（驻军标 `(驻军)`）。建造即时（ADR-0006），故无"建造中"状态 |
| L2 | W3 槽位操作 | 空槽：`建造` `指派`；有建筑：`拆除` `指派` |
| L3 | W4 候选 | 建造候选建筑（含花费、是否负担得起）/ 指派候选英雄（阵营级待命·可用英雄，见 §5.3） |

### 5.2 通用操作

| 按键 | 行为 |
|------|------|
| ↑↓ | 当前层内切换条目 |
| → | 进入下一层（若允许） |
| ← | 回退上一层 |
| 回车 | 等同 `→`（进入下层），或在 W3/W4 执行操作 |
| ESC | 回退一层；在 W1 时退出场景 |

### 5.3 各层进入规则

- **L0 → L1**：在任意据点按 `→`/回车，进入 W2。
- **L1 → L2（槽位）**：焦点在槽位上按 `→`/回车，进入 W3 操作。**非己方据点不可**，日志警告"非己方据点，不可操作"。
- **L1 → 部队操作**：焦点在部队上按 `→`/回车：若是己方非驻军部队，`PUSH ArmyScene({"army_id":...})` 委托部队场景操作（等同于部队一览 §7）；驻军不可编辑。
- **L2 → L3**：建造/指派按 `→`/回车进入 W4 选目标；**拆除直接回车确认**执行（删除该槽位建筑），不进 W4。
- **L3 确认**：回车执行 —— 建造走 `action_build`（资源/槽位校验，支付即即时建成）；指派写入 `player.lords[sh.id]=hero`，候选为**阵营级待命·可用英雄**（ADR-0005，不再限"该据点的无部队英雄"）；执行后回退到 L1。

> 非己方据点可查看 W2，但**不能继续向右操作**（槽位与部队均拒绝）。这把"查看敌方布防"与"操作己方建设"清晰分开。

### 5.4 业务层缺口

> 业务层无据点"拆除/指派领主"接口：拆除用直接 `buildings` 列表删除，指派用直接 `player.lords[sh.id]` 写入（领主占位待重定义，见 §13 代办）。建造走 `Game.action_build`（有资源/槽位校验，即时建成）。这是计划内的占位。

## 7. 部队界面

三窗口 + 九宫格单元格编辑。窗口布局会随焦点是否进入九宫格单元格而**重排**。

### 7.1 布局（3 窗口）

```
┌─ 部队一栏 ─────────────────────────────────────────┐
│ 1 我方   2 敌方   3 驻军   4 全部                    │  ← 筛选行
├──────────────┬──────────────┬───────────────────────┤
│ W1 部队列表  │ W2 部队操作 │ W3 阵型（九宫格）      │
│  ▶ 先锋军    │  移动        │ 规模 6/9  补给 10/10   │
│    守备军    │  编辑        │ 位置 隘口              │
│              │  解散        │ 1列 2列 3列            │
│              │              │ 前排 … … …            │
└──────────────┴──────────────┴───────────────────────┘
1我方 2敌方 3驻军 4全部  N新建(仅W1)  →进入 ←回退  回车确认
```

| 窗口 | 常态（army 模式） | 单元格模式（在 W3 选中某格后进入） |
|------|-------------------|------------------------------|
| W1 | 部队名称列表 | **单元格详情**（单位格=名称/词条/英雄/等级/属性/生命；空格=空位提示+待命·可用数） |
| W2 | **部队操作**：移动 / 编辑 / 解散 | **单元格操作**：单位格=移动 / 下场 / 编辑装备；空格=上场 |
| W3 | 部队占用 + 补给 + 位置 + 九宫格 | 同左（保持阵型显示，光标停在选择格） |

### 7.2 筛选（数字键 1234）

| 键 | 筛选 | 含义 |
|----|------|------|
| 1 | 我方 | 玩家非驻军部队（数字 1 永远是真人玩家） |
| 2 | 敌方 | 其他阵营非驻军部队 |
| 3 | 驻军 | 据点驻军 |
| 4 | 全部 | 全部部队 |

切换筛选时焦点复位。

### 7.3 焦点层级与操作

焦点分三层：W1（level 0）→ W2（level 1）→ W3（level 2）。方向键右逐层进入，左回退。进入 W3 后，方向键上下左右移动九宫格光标（含空格）；空格/回车进入该格的"单元格模式"（W1 变为单元格详情、W2 列出该格可用操作）。

| 按键 | 行为 |
|------|------|
| ↑↓ | W1/W2：当前层内切换条目；W3（非单元格模式）：上下移动九宫格光标 |
| ←→ | W3（非单元格模式）：左右移动九宫格光标；其余层：`→` 进入下一层、`←` 回退一层 |
| 回车 | 进入下一层 / 执行 W2 操作 / W3 选中格进单元格模式 |
| 空格 | W3 选中格进单元格模式（单位格或空格） |
| N | **仅 W1（非单元格模式）**新建部队（§7.5） |
| ESC | 取消子模式 → 退出单元格模式 → 回退一层（W3→W2→W1）→ 退出场景 |

### 7.4 部队操作（W2，army 模式）

仅**本方部队**可操作；非本方/驻军部队 W2 仅可查看，日志警告"非本方部队，不可操作"。

| 操作 | 行为 |
|------|------|
| 移动 | 进入移动模式：W3 列出距当前位置距离 1 的邻接地点（见 §7.6）。若该地有敌方非驻军部队或敌方据点，标 `[攻击]`。回车确认 → `action_move_attack`（移动或攻城）。本回合已行动则警告 |
| 编辑 | 占位：业务层暂未开放，日志警告（区别于单元格内的"编辑装备"已实现，见 §7.7） |
| 解散 | `disband_army`：直接清空九宫格、单位 `army_id=None`，**单位直接丢弃、不进入待命池**。若需保留单位应先在单元格内下场再解散部队 |

### 7.5 新建部队（N，仅 W1）

- 仅当焦点在最左侧窗口（W1、非单元格模式）时可用。
- 建队地点为当前选中部队所在据点（或玩家首都）。队长候选为**阵营级待命·可用英雄**（ADR-0005，不再限"该据点的无部队英雄"）：`create_army` + `set_captain` 建队；若无待命·可用英雄，日志警告。
- 建队后自动切到"我方"筛选并聚焦到新部队。

> 背景：部队必须由英雄任队长，队长的领导力决定部队可承载的占用总和。无英雄则无法建队。

### 7.6 移动与攻击

- 移动以"跳"（Hop）为原子单位，每回合默认 1 跳（跨一个邻接结点）。
- 目的地为距离 1 的邻接结点。若该处有敌方**非驻军**部队，或该处为**敌方据点**，标记 `[攻击]`，本次移动即发起战斗。
- 每支部队每回合**主动发起的战斗最多 1 场**；被动防守不限次。
- 战斗自动结算（200 Tick）；未分胜负则防守方留守、进攻方退回出发结点。

### 7.7 单元格操作（W2，单元格模式）

在 W3 选中某格按空格/回车进入单元格模式，W1 显示该格详情、W2 列出该格可用操作。仅本方非驻军部队可编辑。

选中**单位格** → W2 操作：

| 操作 | 行为 |
|------|------|
| 移动 | 进入移动子模式：W3 九宫格选目标格，回车确认。目标空 = 移过去；目标有单位 = 与之换位（直接 `grid` 槽位交换/移动，统一操作，不再单列"换位"） |
| 下场 | `action_discharge`：该单位进入**待命·不可用**（5 回合冷却，ADR-0005）。**任意位置均可下场**（野外/敌境亦可撤人，代价是 5 回合不可用）。队长下场触发队长继任（见 CONTEXT.md Captain），无可用英雄接任则部队解散 |
| 编辑装备 | `PUSH UnitScene({"unit_id":...})` 委托单位界面（§8）编辑该单位装备 |

选中**空格** → W2 操作：

| 操作 | 行为 |
|------|------|
| 上场 | 进入上场子模式：W3 列**待命·可用**单位，↑↓ 选择，回车 `action_deploy` 编入此格。**部队当前须位于己方据点**（ADR-0005，前线补员要回据点，不可空降）。无待命·可用或部队不在己方据点则日志警告 |

> 单位为 3×3 九宫格，分前/中/后三排；近战只能攻同列或邻列前排，远程/魔法可越排，前排掩护同列后排。移动（含换位）用于调整站位策略。

### 7.8 经据点界面委托进入

据点场景可经 `PUSH ArmyScene({"army_id":...})` 直接聚焦到指定部队，等同于部队一览操作，提供按据点查看部队的入口。

### 7.9 业务层缺口

> 单元格操作（上场/下场/编辑装备）**已实现**：上场 `action_deploy`、下场 `action_discharge`、编辑装备 `action_equip` + 委托 UnitScene；移动（含换位）通过直接 `grid` 槽位交换实现。**部队级"编辑"仍为占位**（日志警告），区别于单元格内的编辑装备。解散当前直接丢弃单位而非进入待命池。指派领主、拆除建筑仍为直接写入占位（见 §5.4）。

## 8. 单位界面（键 X）

跨部队浏览与编辑己方全体单位的全局花名册。从主场景按 `X` 进入；也可经部队界面单元格"编辑装备"委托进入并预选到指定单位。

### 8.1 布局（2 窗口）

```
┌─ 单位一览 ───────────────────────────────────────────────────────────────┐
│ 己方单位 N 名                                                              │
├──────────────────────┬───────────────────────────────────────────────────┤
│ W1 单位列表           │ W2 单位详情                                       │
│  ▶ 骑士王 · 先锋军     │  名称 / 词条 / 英雄 / 所属部队 / 位置              │
│    步兵1 · 先锋军     │  等级/经验 / 生命 / 全属性（3列）                  │
│    步兵2 · 待命·可用  │  维护费 / 训练消耗（或不可训练原因）              │
│    魔法师 · 首都驻军  │  [训练] [装备1:…] [装备2:…] [装备3:…]             │
└──────────────────────┴───────────────────────────────────────────────────┘
↑↓ 选单位  空格/回车 进详情  ESC 返回
```

- **W1 单位列表**：列出己方所有单位，顺序为"场上部队成员 → 待命（可用/不可用）→ 己方据点驻军"。英雄用 ACCENT2，待命单位用 DIM，部队成员用 FG；标签注明所属（如 `· 先锋军`、`· 待命·可用`、`· 待命·不可用3`、`· 首都驻军`）。
- **W2 单位详情**：选中单位的名称、词条、是否英雄、所属部队/位置、等级与经验、生命、全部 16 项属性（3 列布局）、维护费、训练消耗（或不可训练原因），底部 4 个按钮：`训练` + 3 个装备栏。

### 8.2 操作

| 按键 | 行为 |
|------|------|
| ↑↓ | W1：在单位列表中移动焦点（循环）；W2（详情焦点）：在 4 个按钮间循环 |
| 空格 | 切换 W1 ↔ W2 焦点；切进 W2 时按钮焦点复位到"训练" |
| 回车 | W1：进 W2 详情；W2：激活当前按钮（训练 或 进装备选择子模式） |
| ← | W2 焦点切回 W1 |
| ESC | W2 焦点 → 切回 W1；W1 → 退出场景（`POP`）；装备子模式内 → 取消子模式 |

### 8.3 训练按钮

- 走 `Game.action_train`：消耗 `train_cost` 直接获 **+5 XP**（纯整数，溢出原样保留到下一级）；每回合每单位最多 1 次；训练本身不回血，升级时 HP 按比例保留（不回满）。
- 按钮在以下任一条件不满足时**置灰**（回车在日志栏提示原因）：
  - 单位处于"可训练位"（`is_trainable`）：在己方据点内的部队中且该据点无任何敌方部队，**或**为待命·可用（无位置，默认安全）；
  - 本回合该单位尚未训练；
  - 阵营资源负担得起 `train_cost`。

### 8.4 装备栏（3 槽）

- 走 `Game.action_equip`：回车进入神器选择子模式，列出**所有已定义神器**（原型不维护阵营神器库存，占位实现，便于验证 `effects`/`tag_grant` 生效），回车装备到该槽位。槽位越界/神器未知则失败；槽位已占用时替换（旧神器丢弃，原型不回收）。
- **装备不受位置限制**：待命单位、驻军、部队成员均可换装。
- 装备后单位词条重算 = 兵种本体 tag ∪ 当前装备 `tag_grant` 赋予的 tag。

### 8.5 委托进入

部队界面单元格"编辑装备"经 `PUSH UnitScene({"unit_id":...})` 进入并预选到指定单位、直接进 W2 详情（§7.7）。

> 单位界面是全局花名册（跨部队），区别于部队界面（单部队九宫格内编辑，§7）。本场景底部统一日志栏（y=h-2）。

```
↑↓ 切换据点  ←→ 选择英雄  回车 招募  ESC 返回
```

每个窗口显示一名英雄：名称（HEADING）、词条（DIM）、招募费用（充足=GOLD，不足=WARN）、信念要求、基础属性（11 项）、技能（ACCENT2）。空窗口显示"（空位）已被招募"（该槽已招募）或"（空位）等待下次刷新"（无池/刷新未出）。3 个都招满即 3 个空栏位。

### 9.2 操作

| 按键 | 行为 |
|------|------|
| ↑↓ | 切换己方据点（每个据点独立招募池，每 14 天刷新 3 个）。多据点时头部显示 `[i/N] ↑↓切换` |
| ←→ | 在 3 个窗口（英雄）间移动焦点 |
| 回车 | 招募焦点窗口的英雄：走 `action_recruit_hero`（资源/信念校验）；成功则日志 + **留在本场景**（被招募窗口置空，其余英雄原位保留）；失败则日志警告并留在本场景 |
| ESC | 返回枢纽 |

### 9.3 招募后的流程

> 招募成功后**留在本场景**：被招募的窗口置空显示"（空位）已被招募"，其余英雄原位保留，可继续招募直到该据点池满。业务层 `action_recruit_hero` 招募英雄后将其送入**待命·可用**（阵营级、无位置，ADR-0005），**不自动创建部队**——招募只产生英雄单位，不强制其上战场。玩家可后续：
> - 在**单位界面**（§8，X）训练或装备该英雄；
> - 在**部队界面**（§7.5，N 新建）以该英雄任队长新建部队（候选为阵营级待命·可用英雄）；
> - 在**据点界面**（§5.3，L3 指派）将其指派为某据点领主（占位，候选同为阵营级待命·可用英雄）；
> - 在**部队界面**（§7.7，单元格"上场"）将其编入已有部队——须部队位于己方据点。

> 背景：英雄招募消耗资源并需满足信念门槛；每据点独立刷新，每 14 天（一个月相周期）刷 3 个。招募池刷新由业务层 `start_turn` 每 14 天自动执行，TUI 只读 `pool.offerings`。`offerings` 为**固定 3 槽**列表（hero_def id 或 `None` 空位）：招募把对应槽位置 `None`，**不压缩**其余英雄——故三窗口与槽位一一对应，被招募的窗口才空，其余英雄原位保留，直到下次刷新重填 3 槽。每刷新周期、每据点可分次招满 3 名。

## 10. 待命池界面（只读 · 暂未挂接入口）

待命池（Standby）是阵营级的单位候命池，取代并泛化了原"聚贤庄"：全兵种通用、无位置，分**可用**（冷却 0，可派遣到己方据点内的部队、可训练）与**不可用**（下场后 5 回合冷却中，暂不能上场）两态。业务层 `Faction.standby: {unit_id: cooldown}`，冷却在 `start_turn` 推进。`action_recruit_hero` 招募后入待命·可用；`action_discharge` 下场后入待命·不可用（5 回合冷却）。

### 10.1 布局与操作

- 表格三列：**单位**名 | **词条** | **状态**（`可用` / `不可用 N回合`）。
- `↑↓` 切换单位，`ESC` 返回。仅只读浏览。
- 提示："上场请到部队编辑界面"——实际上场走部队界面单元格"上场"操作（§7.7）。

> 待命池场景（`pydemo/tui/scenes/hall.py`，类名 `StandbyScene`）**暂未在主流程挂接入口**（无绑定键）：玩家在招募后可直接在单位/部队/据点界面操作待命·可用单位，无需单独跳转待命池。待命池仅作全局候命一览。`allow_status_overlay=True`（支持 Tab 总览）。本场景底部统一日志栏（y=h-2）。

### 10.2 业务层缺口

> 待命池的冷却推进、上/下场、训练可训练位判定均已实现（`_tick_standby` / `action_deploy` / `action_discharge` / `is_trainable`）。当前缺口见 §13 代办：业务层只有 `action_recruit_hero`，无 `action_recruit_unit`（普通兵招募），故普通兵源除开局场景硬塞的预备兵外无法持续补充。

## 13. 制作约束与后续代办

### 13.1 框架与业务分离

- **框架**（`pyconsole`）可复用、可由本仓库独立演进（源自 `U:\pyFramework` 的副本，现已允许按需扩展，但游戏特定逻辑不得渗入框架——扩展限于通用能力，如键提示栏位置 `hints_row` 与回值通道 `on_return` 这类框架级特性）。
- **业务层**（`pydemo/game/`）为纯逻辑、无 IO，不依赖任何界面。
- **交互层**（`pydemo/tui/`）位于二者之间：用框架的渲染与输入抽象，调用业务层的逻辑函数，把结果以日志/状态反馈给玩家。
- 动作常量分两处：框架导航动作在 `pyconsole.core.actions`，游戏专属动作在 `pydemo.tui.actions`，**不可混用**。
- 可替换性：语言、美术资源、按键绑定在设计上预留接口（动作名抽象、主题色集中、数据 JSON 化）。
- mod 支持：`mods/` 文件夹下同名 JSON 整条覆盖基础定义，实现数值的追加与修改，但主流程硬编码不可改。

### 13.2 后续代办与待明确点

以下为当前代码与设计文档一致后，仍标记为**代办**或**后续需要明确**的点（已落代码的占位/缺口，非本次批次新增）：

1. **普通兵招募动作（用户指定代办，最高优先级）**：业务层仅有 `action_recruit_hero`，无 `action_recruit_unit`（据点 + 兵种 → 招普通兵）。现状靠 [scenario.py](pydemo/cli/scenario.py) 开局硬塞预备兵兜底（双方待命池各 2 个，冷却 0），使起始部队战死后能重建。需新增 `Game.action_recruit_unit` + AI 接此动作 + UI 入口，使兵源可持续；**完成后移除 scenario.py 的初始预备兵兜底**。
2. **领主（Lord）重定义**：建造改为即时（ADR-0006）后，领主原"建造时间 -1 回合"效果失效，`player.lords` 字段保留为占位，职责待重定义或移除。指派领主当前用直接 `player.lords[sh.id]=cid` 写入，无业务层接口。
3. **意志（Will）职责重定义**：`will` 属性暂保留并参与增长（增长率 0.3），但其"决定部队规模"的职责已移交领导力（Leadership），具体用途待重定义。
4. **标志性建筑命名表**：据点总览（§6）的"标志建筑"列直接显示 `landmark_type` 字符串（`weak`/`medium`/`strong`）作占位，无独立命名表。后续加命名表后替换为中文名。
5. **神器库存**：原型不维护阵营神器库存，单位界面装备栏（§8.4）列出所有已定义神器可直接装备（占位实现，便于验证效果）。后续需加库存与获取机制。
6. **存档/读档**：`Game.snapshot()/restore()` 完整序列化留待业务层扩展；当前退出选单的保存/读取仅记录天数（占位）。
7. **外交系统**：业务层无外交系统，外交界面（§4）为占位，仅保证 `J` 键可用。
8. **科技/文化系统**：业务层无科技/文化系统，学习记录保存在 TUI 控制器、资源在 TUI 侧扣除，不影响战斗与经济（占位）。
9. **据点拆除/指派领主接口**：拆除用直接 `buildings` 列表删除，指派用直接 `player.lords[sh.id]` 写入，均无业务层接口（占位）。
10. **部队级"编辑"操作**：部队界面 §7.4 的"编辑"仍为占位（日志警告），区别于单元格内的"编辑装备"（已实现）。
11. **聚贤庄→待命池命名迁移**：原 `hall_of_worthies` 已由 `Faction.standby` 接管（ADR-0005）；`hall.py` 场景类已改名 `StandbyScene`，但文件名仍为 `hall.py`，待后续整体重命名。
